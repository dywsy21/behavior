## 为什么改

### B19：空间配额防止少数高对比角点挤掉其他测量点（20:28，离线候选）

B18真实新图仍以8→4→7点断链，55新控制安全停，不能拿旧帧可通过当作闭环已修好。候选默认关闭`--spatial-grasp-features`，保持原3D局部/本体/稳定深度mask，按4×4固定图像区域各最多10角点、每区同0.015相对质量；全局仍160点/7px间距。图像导数在整图计算、不用裁边制造角点。该变更是候选测量的空间覆盖与局部对比归一化，不放宽后续光流、3D一致性、8点/80%或连续位移门；持续轨迹仍绑定图像/目标/执行身份。

旧14对中，B17末对16点/93.75%、B14末对18/100%，标准B13末三对21/22/17、均100%且原累计门通过；空抓16/30点但0%跟手仍拒绝，亚分辨率微抬仍拒绝。241CPU通过，包括强角点不能压掉其他区域弱角点、当前mask、预算/间距与显式开关。新B18三对与人工叠图未验前不放行物理；预算见h08_b19，尚无新物理结果。

### B18：测量特征应有时间身份，不能每帧任意换一组（20:05，离线通过）

B17同起点物理在第三次抬升因仅4个RGB-D对应而安全停，未到新持物观察；前两对11/10个点全跟手，但累计实测14.615mm仍未达原15mm门。统一25mm深度域后引入的近处强角点会改变相对质量排名，单纯在光流后剔除深度边界不足以稳定选择。离线分解：B17末对冷重检4、持续6、先屏蔽已知3×3无效深度区7、两者组合8且87.5%跟随；B14组合12/100%。空抓与不足位移负例不通过，标准25/26依然不可验证。既不减8点要求，也不把14.6mm改判为15mm。

默认关闭`--persistent-grasp-tracks`：仅已通过上一对刚性跟随的手保留像素轨迹，绑定原图hash、goal和真实执行号；下一帧重新检查同一目标3D邻域、本体排除、前后光流、稳定深度和空间跨度。沿用160点总量/7px间距，旧点优先、新检测补足；失败/否定/断档清空，不从别的手/目标借证据。所有≥8点/80%/连续累计门和原三次探测上限保留。当前仅CPU与保存帧可通过，须新物理复验；不是已经解决特征贫乏的所有抓取。

### B17：语义关系与视觉可见性必须分开（19:36，静态通过、物理待验）

B16两静态中，按钮不可见时观察器仍把reference答成unknown；因此没有放行B16物理。B17新增独立text-only有限选择，只输入当前goal和**先前观察验证**的持物标签，输出world/held_left/held_right/unknown。它不接收当前图像、对象坐标或仿真附着；参考手是拿物体的手，不是执行下一操作的手。无已验证持物时直接world，否则每goal最多一次推理、每回合最多4次；保留unknown且未知/矛盾/未验证手停止。绑定后视觉仍独立判断visible/像素/危险，不允许视觉unknown抹掉任务关系。保存B14d4实测1次生成held_right，B8d33无held无需推理得到world；12个fine持物候选预检通过。这只是关系接口和可执行性，不代表按钮已找到。

B14真实结果已更正：注册反馈在d3通过、转到press并经过HOLD切换屏障，之后28次错误世界扫描、官方false。B15tracking-anchor提示对两坏帧未改善，第三帧6图与脚本9图假设冲突而退出；没有运行后两例、没有B15物理，生产不启用该提示。25mm深度域一致保留，仍不足以解决所有近距离跟踪失败。下文“待验”均为当时历史。

### B16：手持物上的目标不能用世界航向搜索（19:16，本地实现）

B14已经实测通过抓取反馈并切到左手按按钮，却因按钮不可见而转底盘28次；持物手、对象、腕相机及头部一起转，根本未改变相互视角。新默认关闭`--held-object-inspection`让观察器显式区分`world / held_left / held_right / unknown`。这是当前目标与已有持物声明的语义关系，不是仿真位置/附着真值，也不由“哪只手操作”或“哪个相机看见”决定。当前目标关系一旦明确就锁定；矛盾、无已验证持物的held引用或带载搜索仍未知时停止保持，不猜测世界位置。

真实机载抓取验证后，保存目标表面点在持物手坐标中的旧锚点，仅用来预估头相机中的取景，不充当当前按钮检测或完整物体pose。手持物搜索只给持物手小平移/工具轴小转动，保持闭合，禁止底盘/躯干搜索、开爪以及借另一工作手冒充观测变化。相同SafeServo/深度预检逐动作执行；原持平约束禁止转腕。VLM在这些真实可执行候选中选择如何把物体呈现给头相机、再暴露另一侧；下一帧真看到按钮后才恢复原操作接口。每goal最多24次、累计头—手相对路径20cm/转动60°；单纯底盘共同转动不刷新观察进度。固定2保存观察与1个持物姿态预检先验证，尚无新物理效果。

### B15候选：接触点不等于视觉跟踪锚点（19:03，尚仅静态验收）

标准B13的验证种子深度32–33mm，原定位模块接受>25mm、跟踪却要求>40mm，形成接口矛盾；统一最低有效深度到既有定位的25mm，并在失败回执记录有效像素、机器人排除与特征数。原运动/空间分布/重复/误差门不改，也不把真实硬件近距能力等同仿真深度。此修复仍不足：标准两个坏对只剩4/6个有效对应，必须继续拒绝。额外深度边缘预屏蔽未解决，作为失败候选保留证据、不部署。

新候选仅在注册VERIFY_GRASP观察中要求在同一目标上选择可跟踪的刚性图案/角点，而不是继续点击抓取接触或图像中心；当前/历史9图及控制/成功语义不变，未知仍未知。这是测量锚点，不是新抓取姿态，其他阶段继续原接触点接口。先4保存帧/4调用/0控制静态对照与人工核验，尚未证明闭环效果。

### B14：验证动作必须满足传感器可测尺度（18:45，本地通过、真实待验）

B13匹配诊断中，物体始终在手，但VLM在两次1cm抬升之间选了2mm；实际世界抬升仅0.994mm，无法满足≥3mm的单对运动验证，连续计数被清零。不是靠延长窗口或降低成功阈值解决：将VERIFY_GRASP中的动作选择收回给**通用主动感知控制器**，每次只做新鲜预检已通过的1cm抬手，再重新观察；原四观察/最多三探测、≥2连续/累计15mm/向上12mm、自几何排除等均不变。目标不可见、显式否定、危险或1cm动作不安全时保持载荷并停止，不退化到不可测小动作，更不声明成功。左右/双手使用同一逻辑，与对象名无关；VLM仍负责目标、接近与操作，且观察调用照常运行，省掉验证动作选择调用。210CPU通过，原B13标准回合另有失败，不能预设此一修复已解决所有反馈问题。

### H-08 B7：把抓取尝试与成功验证分开（2026-09-18，待真实闭环）

- RGB-D读取前执行4次仅渲染更新，三相机RGB/深度共享snapshot编号，采集前后本体q必须静止。reset后annotator可能残留旧视角，不能因数组大小/hash合法就认为是当前图；d2da0ac的task3第一帧已人工发现此问题，保留作回归，不冒称搜索成功。渲染刷新方案仍须新物理门核验，不消耗机器人动作步。

- VLM只允许返回当前可行列表中的一个动作。执行前再次读取q并做完整预检，执行中的失跟踪/限位/自碰撞停止仍生效。候选预检从主控制器的**命令锁存**复制夹爪状态，不能从持物时的开度推回成打开指令。
- 底盘平移另外检查当前可见深度覆盖与近场障碍；没看过的后方不当成自由空间。可见点云、0.34m底盘圆和手臂胶囊只是保守局部否决器，**不是完整环境碰撞规划**，未观测障碍/被持物几何仍有局限。控制门中的显式运动是单独登记的工程检查，不称已通过全场景避障。
- 看不见目标时，搜索器选择单次8°扫描，不必再向VLM问一个毫无几何依据的小动作；每个动作后仍调用VLM重新观察。完整本地扫描找不到目标时，允许VLM基于当前图像选择左右扫描/有限可见方向换位/停止。换位最多5次6cm，每步重新检查，不是一口气走30cm。累计搜索平移≤1.2m、绝对转角≤720°，另受回合决策/控制/墙钟上限约束。
- 恢复仅调整当前策略，不改原目标序列、完成记录或持物占用；最多2次，不能消除硬安全停止。达到任何预算都明确记录原因，不把“所有计划用完”视为任务成功。

## 仍然有限的地方

### H-08 B4：观察隔离、候选完整性与自身外壳

观察器不再接收上帧目标像素/3D点、候选收益和搜索覆盖；只给当前子目标、本体、最后实际动作与运动，以及标明时间的图像。动作选择器仍接收本轮几何和执行反馈。四保存状态验证减少了重复旧数值，但边缘桌面/椅背定位仍不完全可靠，不能称此修改解决了VLM空间理解。

动作候选按不同物理方向分配，包含相机坐标对角方向及每个方向2mm备选，不让不可达forward耗尽平移槽。ALIGN保留1°和3°六轴旋转；未持任何物体的pick可以提出2cm底盘/3mm躯干调整，仍经过新鲜深度、关节及路径门。接触点超过10cm退回APPROACH，进入ALIGN仍为8cm；不因阶段自报而认证抓取。里程计后的停止判断明确保留原最多两次策略恢复权限，不能提前短路或擦掉硬停止。

两腕能看见自身底盘壳体；只剔除手臂胶囊/夹爪会把壳体当障碍，使所有底盘平移被拒。B4从**机器人定义指定的base_footprint_link**导出其visual mesh，保留完整局部三角面和FK；只有到该表面≤6mm的深度点作为自身回波排除，不按整个包围盒或任意近体区域删除。其余视图和外界点仍参与避障，自身点不能认证外界自由空间。没有场景语义分割、物体或全局pose输入。贴壳外物与深度误差、其余本体部分、未见障碍仍是局限；真实导出/门待验证，不能冒称完整碰撞安全。

### H-08新增：经过RGB-D核验的底盘运动记忆

旧逻辑将30Hz采样的底盘关节角速度积分直接当真实朝向。工程probe确认每步确实1/30秒，但实际每次约6.92°，积分却随方向/时刻为7–9°；由此会提前标记“已经扫完一圈”，也会误报底盘未达标。不是简单dt错误，不能套经验倍率。

`--visual-odometry`使用当前/上次head RGB-D、相机内参以及随本体q变化的相机外参估计相邻机身运动：SIFT匹配＋两端稳定深度＋RANSAC/PnP＋重投影和3D对应一致性检查。至少25内点、45%支持，像素中位误差≤1、3D中位误差≤1.5cm，并有单微动作位移硬界。新观察通过后才累积覆盖；失败安全停，不退回旧偏置积分，也不使用仿真真位姿、全局地图或目标真值。深度不足/纹理不足及动态场景仍是明确限制。

VLM下一次观察前接收已经修正的本体运动反馈，原速度积分留在`base_velocity_integral_raw`和原执行日志；仅旧“底盘残差”通过/失败可以按新测量重判，碰撞、关节限位、失跟踪、中断等硬停止不能擦掉。原SafeServo控制轨迹不改，动作23维与时间尺度不变。

工程真位移只由独立probe写入诊断文件，不属于生产估计器输入。回放原两策略55相邻对和probe9对全部通过；probe位置分量最大差1.92/4.24mm、转角最大差0.127°。这是局部开发验收，不是全场景SLAM或无漂移保证。开关/源digest绑定新的真实门，旧门不能放行。

### H-08新增：可拒绝的局部表面细定位

`--refine-grounding`是独立开关，默认为false，不改变旧H-07/B1。自由输出UV被原深度判据拒绝时，`affordance.py`在同一相机/同一时刻的小窗口内用原5×5深度门提出最多12点。原始局部图与编号图分开提供，VLM通过`ground`有限语法返回`candidate_id`或null；绝不自动选择最近点。放大只用已有像素，不引入检测/分割真值或新图像信息。

每回合最多16次附加选择，未见目标/无稳定点/已有效/抓取与完成验证阶段不调用。新点丢弃未重新确认的跨视图对应和随动声明，不能认证持物；只有通过当前状态的原动作预检才可执行。服务声明支持ground后才允许refined回合；控制门同时绑定源digest与开关。记录原观察原文、候选、裁剪、原深度拒绝、模型选择及新预检，允许离线定位是识别、选点还是控制失败。

`static_refine.py`固定旧H-07两个radio状态（call4/6），最多2次神经选择/0执行，另有prepare-only供人工先检查。104项本地和robo CPU回归通过；当前真实选点/物理收益仍待H-08验收，不能以“稳定深度”证明“可抓取姿态”。[新实验及预算](experiments/2026-09-18-semantic-agent-effect.md)

RGB-D点定位并不解决可抓取姿态、遮挡关系、长距离SLAM或有接触操作。7cm跨视图阈值用于拒绝明显不同点，不代表7cm操作精度；表面点也可能是模型误指的背景。机器人夹持中心只在实际开合/多姿态门验证后使用，不盲目信任18维FK能表示手指自由度。

高层与精确微动作依然分离，FM/MEM-Lite对照未修改。以后若引入VLA技能或微调，应明确目标/同状态动作监督，不能将本轮“通过安全门”当训练标签或方法已胜出的证据。
