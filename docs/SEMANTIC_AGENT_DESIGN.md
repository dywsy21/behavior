# R1Pro语义微动作：让VLM选择小步，让控制器负责关节

负责人：Codex；接口`r1pro-semantic-v1`，prompt `r1pro-task-advice-v1`。
状态：实验分支实现中，CPU门已通过；物理验证和模型实测以[本轮报告](experiments/2026-09-17-semantic-agent-pilot.md)为准。不是正式参赛提交。

## 设计的出发点

不用VLM报23个连续控制数，也不提供会自动完成整段抓取的`grasp(radio)`。它每次只说“右手向前2厘米”“左夹爪闭合”“底盘左转5度”，实际执行后再看图、看误差，决定下一小步。这是借鉴Show-Harness的**微动作接口思想**，不是把其Franka/Piper代码或微调adapter直接套到R1Pro。

新增模块完全独立于G0.5动作token、FM专家和旧MEM-Lite权重。现有FM实验不改；没有把两路控制信号混合。当前先用任务策略prompt＋最近五条实际执行命令＋上一次实测回执，避免同时引入旧B-final的错误记忆/完成判断。以后需要跨房间搜索或长阶段管理，可加独立规划器维护“已观察事实、待验证假设、当前子目标”，仍通过同一个接口执行；不是必须把MEM-Lite训进模型。

## 本体接口

所有方向采用**机器人当前底盘坐标**：前x、左y、上z；不是“画面左边”，也不是不断变化的腕相机坐标。相机都是原始、不镜像。旋转为围绕该坐标轴的右手定则。每个微动作开始时固定目标，不在每个物理帧重复加位移。

| 部位 | 例子 | 默认幅度/含义 |
| --- | --- | --- |
| 左/右末端 | `R UP FINE`、`L FWD COARSE` | 2/5cm，保留姿态 |
| 末端旋转 | `R YAW_POS FINE` | 5/15°；支持roll/pitch/yaw正负 |
| 夹爪 | `R CLOSE`、`L OPEN` | 只开合，不暗含找物体/自动抓取 |
| 双臂同步 | `BOTH UP FINE`，或`L UP FINE ; R DOWN FINE` | 同一个物理时钟执行两侧目标 |
| 底盘 | `BASE FWD FINE`、`BASE YAW_POS FINE` | 6/15cm或5/15°；有限平滑脉冲、最后归零速度 |
| 四关节躯干 | `TORSO UP FINE` | 顶部平移1.5/3cm，协调四关节、保持顶部姿态；支持前后/上下 |
| 保持/停机 | `HOLD`、`DONE` | HOLD保留姿态与夹爪命令；DONE仅请求停机，不证明任务成功 |
| 搬运保护 | `MODE CARRY` / `MODE NORMAL` | 手臂步长降至1cm、底盘更慢、禁止转腕；**保留当前姿态，不是自动把歪盘扶平** |

动作是短文本DSL，不引入新特殊token。无效/歧义/过长输出拒绝执行并回传错误；不悄悄用FM或全零关节兜底。两手可以并行，底盘/躯干和手臂的任意混合暂不开放，以减少首版不可检查的耦合。头部相机配置为NullController，没有假造一个可转头工具；通过底盘/躯干改变视角。

首测通用2B生成不合法的`L CLOSE FINE`后，增加可选**语法受限解码**：只允许合法命令的token前缀，模型仍决定部位/方向/粒度。旧未约束失败保留；受限模式格式通过是工程保证，不是“模型天生100%遵循指令”。这没有强制它选择右手、目标或正确动作。

原生23维不变：`base[3] + trunk[4] + left_arm[7] + left_gripper[1] + right_arm[7] + right_gripper[1]`。从真实机器人controller metadata核对索引，错误布局立即拒绝。与G05的27维padding没有关系；底盘和躯干均实际受控。

## 一句话怎样变成关节动作

1. 读取当前机器人自身的关节、局部末端姿态与运动学Jacobian。
2. 例如“右手上移2cm”，构造相对起点的末端目标；其他部位保持。
3. 在24个30Hz物理控制帧内，用平滑插值和阻尼最小二乘IK逐帧追踪；CARRY用30帧、更小关节更新。最后四分之一时间保持终点，供伺服收敛。
4. 原配置的绝对关节位置控制器执行23维命令；夹爪目标持续锁存，走路时不会忘记闭合。移动躯干时，两臂末端目标保持在底盘坐标系中，由手臂IK补偿，而不是让手跟着躯干突然抬起。
5. 回传**实际位移、终点误差、姿态误差、关节限位次数、实测夹爪宽度、局部速度积分**。模型下过命令和实际做到分开记录。

底盘动作控制的是速度，使用平滑脉冲及已知controller缩放；距离是指令积分，不保证与实际行走距离完全相同。回执里的局部速度积分不是全局定位，也不是精确SE(2)里程计。持盘时没有假装实现世界坐标的绝对末端锁定；手臂跟随底盘运输。

## 安全与观测边界

- 首版有限步长、关节更新限速、真实关节限位、双末端8cm间距拒绝及CARRY转腕禁令。**这不是完整的自碰撞/环境碰撞规划器**，也没有实现真实力控、自动水平校正或食物滑落检测；不能把软提示当已实现能力。
- 仿真已有`self_collisions:true`、`grasping_mode:assisted`，两者未改。接触附近用FINE，追踪不良要重看和恢复；后续应增加合法RGB-D障碍/接触监测，不读取GT障碍物位置。
- VLM仅收三RGB、机器人局部末端位置/姿态、夹爪读数、任务文本、命令历史和实测回执。没有物体真值ID/位置、BDDL状态、机器人全局真值位姿。官方结果独立写评估文件，**不反馈给actor**。
- 开发适配器使用OG原生机器人相对运动学（与其IK控制器同类量），不访问场景对象。**正式远程policy仍需用本体模型＋传入proprio实现FK/Jacobian，或提交官方允许的IK controller配置**；当前本地适配器不能冒充已完成正式部署包装。
- `object_holding`默认UNKNOWN。夹爪闭合/手指有间隙不能证明拿对物体；披萨仍在盘上必须另行观察。`DONE`、budget用尽、进程exit0都不算完整任务成功。

## 每任务prompt可行，但要写策略，不写隐藏答案

`src/semantic_robot/prompts.py`把task ID和官方task_name绑定；不匹配就报错，避免指挥错任务。所有任务共享微动作和执行器；任务差异仅在版本化建议，不变成50套控制代码。

**task0 radio：** 优先右手抓稳收音机，微抬后看是否共同运动；右手保持，左手从图像找电源按钮、接近并按下。看不到按钮就调整视角/姿态，不能猜按钮位置。抓空则重新对齐，不能连续空夹；发出CLOSE不等于抓稳，碰到也不等于开机。若当前摆放不支持默认手臂分配，要允许重新摆位而非死按脚本。

**task3 plates/food：** 两张披萨分别留在各自盘中，进同一冰箱；两个碗进同一水槽，最后关冰箱。先准备通路和打开冰箱，再端盘；抓盘边缘而非推食物，启用CARRY，小步抬起和移动，视觉检查盘与披萨关系。有承托再松手；食物滑落先停止重评，不把运输空盘当完成。

“不要掉”作为prompt能帮助选策略，但不是物理约束。这里真实落实的是缩步、平滑、转腕锁定及夹爪保持；其余效果必须看实测。一次任务成功也不能证明prompt泛化有效；任务提示词对照应保持模型、实例、预算和控制器相同。

## 速度与模型选择

Show-Harness图8的Qwen3.5 0.8B/2B/9B延迟27/39/79ms，正文硬件为RTX5090；这既不是A100结果，也不是我们三相机＋本体＋双臂DSL的端到端速度。论文的快模型还经过专门微调，不能称通用2B零样本已达到同样操控能力。[论文](https://arxiv.org/pdf/2609.10522)

首选实测**Qwen3.5-2B**，允许以**4B**作同输入复核：开源、无门控下载、本地bf16可用，论文有同系依据；先不用单臂prompt-v3 adapter，因为其视角/前后交换/动作字典与R1Pro不一致。[官方2B模型](https://huggingface.co/Qwen/Qwen3.5-2B)、[4B模型](https://huggingface.co/Qwen/Qwen3.5-4B)

同时查过较新的[Gemma4 E2B/E4B](https://huggingface.co/google/gemma-4-E4B-it)：小视觉编码器是优点，但“E”指有效参数，含embedding分别约5.1B/8B，不等于2B/4B显存；本轮不额外引入第三套依赖与模型。[InternVL3.5-2B](https://huggingface.co/OpenGVLab/InternVL3_5-2B-HF)可作以后替代，不能凭通用榜单断言机器人最好。更近的[Qwen3.8-27B](https://huggingface.co/Qwen/Qwen3.8-27B)加强agent能力，但不是本轮低延迟小模型候选。

必须分开报：①VLM预处理＋生成＋传输；②微动作内30Hz控制时钟；③模拟器实际步/墙钟秒；④完整一轮看图→决策→执行的频率。首版同步仿真等待VLM时暂停物理，这不是现实机器人实时稳定性的证明。HF/SDPA首测也不是vLLM/编译/MTP优化后的速度上限。

## 代码入口与下一步

- `src/semantic_robot/actions.py`：文本→有限微动作；`control.py`：运动目标→23维；`og_backend.py`：仅机器人运动学适配。
- `prompts.py`：共用系统提示与任务建议；`client.py`：不自动重试的本地模型调用。
- `scripts/semantic_robot/serve_vlm.py`：单A100、bf16、固定revision、关闭thinking、最多48输出token、有总调用限额。
- `scripts/semantic_robot/run_sim.py`：不可变commit/原config/原train初态、物理帧与决策分别计时、逐决策图像/prompt/动作/回执、视频和独立官方结果。
- CPU：`PYTHONPATH=src python -m unittest discover -s tests/semantic_robot -v`。

先过真实控制门，再看小VLM是否能选对方向/步长/接触时机；若格式正常而视觉对齐差，优先补R1Pro同接口数据/强teacher纠正，**不拿新训练掩盖控制器错误**。微调数据、长记忆、深度感知、通用RL及正式v3.9.2包装均另立有界任务，不在本轮自动扩展。
