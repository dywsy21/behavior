# MEM-Lite v10：改进、5000步训练与验收结果

2026-09-08。**本轮改进和训练已完成，但效果不达标，不能说原地打转已被根治。** 有些任务的连续同向旋转明显减少；动作转换、有效操作和恢复触发仍有问题。

## 1. 已交付的代码与权重

主仓库仍为 `robo:/mnt/sdc1/robodojo/GalaxeaVLA`。保留队友原有未提交修改，没有重置仓库。本轮实现了：低层速度历史的显式缺失表示与dropout、任务/动作转换均衡采样、lower-body动作token加权、真实恢复数据、高层执行反馈和无进展监控，以及未裁剪真实状态的相对动作还原。

训练保持纯AR，4×A100 80GB，全局batch32、LR=2e-5。从v9 step5000权重初始化，使用全新optimizer/scheduler，**另完成5000个更新步**，不是把旧步数算进去。训练约13小时38分钟，09月08日07:28北京时间保存最终权重。

## 2. 五任务自主仿真：有行为变化，没有任务成功

每任务只测试public_test instance301、seed0一次。配置`max_steps=2048`；此版本官方超时检查发生在计数递增前，实际执行2049步，即68.3秒仿真时间。**这是一组短时诊断，不是完整任务时长、多实例的官方成功率。** 五例全部预算截断，success均为false、最终q_score均为0。

## 3. 留出动作检查：该转通常会转，该停仍不可靠

307个活动分层留出样本中，271个低层动作全部完整解码，36个高层输出全部协议合法且未截断。低层使用真实intent，因此这是分层诊断，不是完整端到端成功率，也不是全eval集分布估计。

| 检查 | 通过数 |
|---|---:|
| 必要转向：末四步均朝正确方向，幅值>0.05 | 38/40 |
| 启动转向 | 17/40 |
| 换向 | 10/30 |
| 转向结束：末四步均满足`|yaw|≤0.02` | 15/40 |
| 已静止时保持不转 | 34/40 |
| 恢复刹车 | 1/12 |
| 恢复后稳定停转 | 11/12 |

高层intent与参考完全一致30/36。人工检查六个不一致例子：五个在参考标签转回原操作时继续输出恢复intent，一个抽屉侧别与参考不一致。状态格式正确不能代替语义正确，但也不能仅凭字面不一致就断言所有替代决策都是错的。

另12个“真实刹车后观测＋刹车前记忆”的条件探针全部输出了预期恢复intent和REPLAN。这证明模型在这些输入上学会了恢复协议，**不证明真实在线恢复成功**。它们不与307个样本混算。

## 4. 新发现的根本障碍：正确token也可能不是正确刹车

我对全部271个低层样本做了独立CPU codec往返检查：直接把专家动作编码为目标token，再解码，不调用VLM。

| 检查 | 恢复刹车12例 | 普通停转40例 |
|---|---:|---:|
| 模型实际预测能停 | 1/12 | 15/40 |
| 正确目标token解码后能停 | 1/12 | 37/40 |
| 仅把后16步底盘保持为第16步的值，再编码解码 | 12/12 | 40/40 |

恢复刹车样本的前16步专家底盘指令全为零，后16步通常开始重新对准。第三行**完全保留前16步真实动作**，只改动尚不会执行的后半段底盘指令。结果证明当前32步整块动作压缩会让未来转向影响前16步的刹车表示。

三个案例的底盘token教师强制准确率已经100%，自由预测的前16步底盘动作也与目标token重建近乎一致，最大差异约6.2e−6；但末四步yaw仍约0.046–0.050。这解释了为什么某些样本CE低至0.001附近，实际却不能停。

这不是证明码本完全不能表示零速度，也不能把全部失败归给codec。模型与目标codec通过的那一个恢复样本并不是同一个；其他样本还存在额外的token预测错误。普通停转的目标codec可通过37/40，模型仅15/40，说明转换决策本身仍不足。

此前42例测试主要证明常值停转和双向转动可表示，不能推广成“所有转换窗口都没有codec问题”。我已在[根因报告第7节](MEMLITE_V9_SPIN_ROOT_CAUSE.md)补充并收窄原表述。

## 5. 不利证据：CE改善并不等于动作改善

复用历史25个固定留出窗口，只运行新权重，旧模型输出取自原始记录。相同目标token、相同推理精度，保留全部样本；新策略包含预期的速度遮蔽，因此不是单项改动的消融。

| 指标 | v9 | v10 |
|---|---:|---:|
| 底盘/躯干token的普通CE | 1.5319 | 1.3998 |
| 该组token准确率 | 63.25% | 64.75% |
| 两臂token合并准确率 | 19.13% | 21.13% |
| 前16步yaw平均绝对误差 | 0.02437 | 0.03865 |

这25个样本中，收音机、垃圾、装饰任务的yaw误差变差，餐盘和罐装肉改善。样本仅来自每任务一个episode的五个选定窗口，不能推广为全分布，但足以否定“所有任务都稳定变好”的说法。两臂token准确率也不能直接当作抓取成功率。

## 6. 恢复监控在线没有发挥作用

五任务均调用高层17次，各任务始终保持同一个intent；没有任何`no_progress_detected`、恢复暂停或恢复退出事件。意图重复本身未必错——操作未完成可以继续同一意图——但此处不能宣称恢复闭环已经生效。

根据真实观测请求重建数值运动条件，万圣节有26对、罐装肉有12对历史窗口满足旋转量、时间及平移路程门槛，实际仍没有触发。审计没有重放原始RGB相似度和所有监控状态，**所以目前只能把RGB重复判定列为重点待查项，不能冒充已完成的完整门控归因**。

## 7. 接下来应该改什么

不建议直接按同一配方再堆5000步。更合理的下一轮顺序是：

1. **让动作token监督对齐实际16步执行区间。** 先验证前16步监督＋后段保持填充，或分块独立/因果codec；同时检查全身动作、刹车、换向与夹爪事件。当前只验证了底盘反事实，尚未把它变成训练配方。
2. **把恢复意图区分为可执行阶段。** 刹车、对准、接近、恢复原操作不应只挤在同一句宽泛intent里；阶段切换须有真实观测监督，并重点补足恢复退出和操作开始的样本。
3. **补齐真实在线恢复触发与验收。** 记录每次门控的数值及视觉相似度，在训练实例上校准对视角/躯干变化更稳健的进展判断；不能继续只靠12个离线协议探针。保持不向策略输入特权目标坐标，并补充新策略实际到达的失败状态和纠正操作示范。

上述是下一轮建议，**没有偷偷应用到本轮v10、修改本轮监督或又启动训练**。本轮是完成了一次可追溯的改进实验，而不是已经获得了可用的五任务策略。
