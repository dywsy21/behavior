# MEM-Lite：实际推理偏差与修复依据

2026-09-12。本人独立检查和执行，无 subagent。当前结论是找到了两个真实部署 bug，**不是已经证明它们解释全部失败，更不是成功率已经提高**。

## 两个具体错误

1. **FM 收到了训练时不存在的补齐噪声。** 机器人实际输出23维控制，模型用27维合并表示，`[7,8,17,18]`是四个补齐位。训练把这些位置置零；原纯FM推理不处理动作标签，因此没有创建动作mask，实际传入None。新修复从机器人静态动作元数据生成mask，初始噪声和每个FM积分步均按已有FM实现清零。所有真实手臂、夹爪、底盘和躯干控制仍保留。
2. **图像历史错误地改变了动作起点。** 模型看到过去6帧图像，但动作目标从当前时刻开始，没有5步历史动作。原通用processor默认从`num_obs_steps-1`开始执行，实际执行预测动作5–20。修复明确从0–15执行；不能把6帧视觉历史当作5步动作历史。

这两处都发生在部署输入/输出约定，修改它们不需要重新训练，且本轮保持同一份A3 step5000权重、同归一化、同图像历史和同物理控制。

## 证据，不只是读代码猜测

- 42个实际原训练锚点的未来动作目标逐值对齐；末窗口的padding及真实clamp边界单独处理。
- 504次受控生成覆盖原始/重放图像与本体输入、直接/原生推理及mask开关。
- 相同输入下，训练源与服务源84/84逐值一致，直接prefill与原生生成84/84逐值一致。
- 84条旧实际网络返回动作全部逐值等于复现原预测的`5:21`；不是把视觉差异误认为神经路径改变。
- 旧无mask输出的4个补齐位绝对值最大约2.66–2.73；正确mask下所有位置精确为0。

核心机器可读证据位于robo的`/mnt/sdc1/robodojo/behavior_dev/direct_execution_L6rqZ6_20260910/a3_input_route_factorial_v2/`：`result.json` SHA `4e6bfb118467a4416e5209f81909fbb15604e014e043cd0481607787ee7f47a0`；`execution_alignment_analysis_v1.json` SHA `97d7cb504c8dfabfce66348cd6cd698b8569cca2ef9501ea21a5826c37f47d71`。本地副本在`/home/wsy/behavior/memlite-resume.L6rqZ6/a3_input_route_factorial_v2/`。

下表为同42个真实原动作回放输入，与原有效绝对控制比较的右臂7关节RMS误差均值，单位rad；不是FM loss，也不是成功率。两个seed使用相同输入，mask和执行起点构成2×2对照。

| 旧：无mask、起点5 | 0.018022 | 0.021554 |

均值分别下降约3.8%和17.6%，但13个明显运动锚点中，两处修正后预测优于“保持当前姿态”的仅6/13和4/13。原演示动作不是唯一成功动作，不能把动作差异直接当物理失败；同样不能因平均误差降低就宣称能够抓稳。关键动作偏弱的问题还需要闭环和进一步训练诊断。

先前直接比较“原训练输入”和“回放输入”时还同时改变了mask与动作起点，存在混杂。因此不能根据那个差异单独断言图像采样/视觉域是根因。

## 实际修复和下一道验收

独立运行目录为`native_a3_aligned_prefix_runtime_v2`及`native_a3_aligned_full_runtime_v2`，保留所有旧服务/日志/结果不动。静态mask加动作起点的16项测试、分析器6项测试、历史与真实传输19项回归通过。A3权重SHA仍为`865193f1c8a257d72ea159bd7a46cebf945b0fd24905110b831f0e8a3438e940`。

新固定GRASP实验`a3_aligned_radio_e121_l1_v2`使用同一个train radio121/instance138、448个原动作前缀、seed17、最多1280个模型控制。原前缀不是模型成绩，固定正确子目标不代表高层有效，也不能把这一例当完整任务成功率。先核验真实网络请求中的mask/历史/权重/执行起点，再跑闭环并由本人看视频。

如果仍失败，保留失败并继续针对剩余低层进展、意图服从和完成反馈的学习问题；不以继续增加训练步数或新增模块来掩盖尚未排除的输入/动作约定问题。最终结果需要修正版的真实完整任务评估，旧A3五任务0/5是含上述部署bug的开发结果，不足以单独否定MEM-Lite架构。
