# v9 低层动作离线诊断（25 个选点，非成功率）

## 范围

同一 v9 step5000 权重；每 task 一个留出 episode（190/390/590/790/990），各选起点、首次夹爪切换附近、中点、大关节增量和大姿态窗口。使用真实示范的三相机六帧历史、proprio 和标注意图，跳过高层规划。25 行均完成 AR 生成，六组动作没有缺失。没有训练或修改正在评测的代码，也不是非 MEM 基线。

## 汇总

下表是选点诊断的算术平均，不代表全 eval 集分布。右夹爪错误率仅在这些选定窗口内计算；每窗口执行前 16 步，指令取 ±1，故错误步数 = MAE × 16 ÷ 2。

## 可复核的失败

- episode190/frame1105：右臂前16步目标最大增量 0.739576 rad，预测最大增量 0.005937 rad，MAE 0.101560 rad。
- episode990/frame10926：右臂前16步目标最大增量 0.987871 rad，预测最大增量 0.003293 rad，MAE 0.083563 rad。
- episode190/frame915：右夹爪 16 步中 15 步不匹配；此窗口低层 CE 仍为 1.380898。这说明低 CE 的平均值不能替代关键动作核查。
- 五个首次夹爪切换窗口的右夹爪均有 8/16 步不匹配。随后对这同一25窗口实际执行 CPU codec 往返及完整 InputPreprocessor.encode_train：两夹爪32步重建全部0错误，train/eval两种模式各25次，全部监督动作 token 与真实编码目标逐 token 完全相同。由此排除了这些窗口的夹爪编码损失和标签 mask 遗漏；不把它扩张成对所有训练样本的保证。
- 不能概括成“模型永远输出零”：episode790/frame13093 的右臂预测最大增量 0.962624 rad，而目标是 0.655316；frame14002 的左臂预测最大增量 0.765886 rad，目标 1.306459。存在过大与过小两类预测。

给定正确意图和真实示范观测仍出现机械臂预测错误，至少这些错误不能只归因于高层记忆或闭环分布偏移。该实验没有识别出唯一因果机制，也没有测量模拟器成功率。

## 口径和限制

- 这25窗口每条有63个受监督 token，其中动作60个：两级残差的左臂、右臂、下半身各16个 payload；两夹爪各2个 payload；另有8个动作 marker 和3个其他监督 token。两夹爪实际 payload 仅4/63（约6.35%）；当前平均 CE 并不按动作部位等权。这是损失分配事实，不单独证明调整权重就能提高成功率。详见 `memlite-v9-probe-supervision-audit.json`。
- CE 使用 bf16 serving 权重的现有数值，在线性输出投影/CE 内拷贝为 fp32 计算；参数本身未修改。它不是训练时 fp32 权重的逐位一致复算，也不是所有 token 指标都完全可与训练日志互换。
- 首次探针在 fused CE 的 hidden/head dtype 不匹配处退出，无输出；v3 只在该独立诊断实例中替换 CE 计算，再在 AR 生成前恢复。正式训练、策略服务未被修改。
- 机械臂误差基于反归一化后的相对增量，尚未恢复绝对动作锚点；保留现有逆变换边界。target_abs_max 可能已经受该边界影响，不等同原始极值。
- raw_max_32step_arm_delta 是32步选点量，不能混作前16步指标。
- 未保存生成 token 序列或完整预测向量，不能从本报告事后恢复逐 token 原因。
- 独立推理使用物理GPU3的空余显存，allocator上限25%，峰值 reserved 12,585,009,152 bytes。进程已 exit0，19:41 UTC复查 GPU3 回到约26GB正式任务占用。
- 本人读完全部25行结果；没有把这说成对25组诊断图像的人工视觉审阅。此前本人查看的28张是正式闭环 bridge 原始相机图。
