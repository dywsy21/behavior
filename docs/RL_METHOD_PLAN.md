# 通用RL后训练：候选与验证计划

## 2026-10-09：反馈闭环＋rollout数据回流＋短技能RL总体方案（设计版）

**11:17 CST / Codex / RL-RECOVERY-LOOP-DESIGN。** 用户认可上轮诊断的三项方向，并要求考虑把RL rollout清洗为训练数据，**本轮先设计总体方案**。本节是下一轮实施设计，不是新run已启动/数据已验收，也不据此停止、热改或延长当前24h作业。旧公共全量评测继续取消。下方11:04审计及10/08实现作为事实基线保留；本节覆盖当时“后继方向尚未认可”的状态，不覆盖实际训练/数据验收状态。

### 1. 主假设与路线选择

主要假设：当前缺少的是**看懂执行结果→改变下一意图→练到正确动作→保住局部进展**的闭环；有质量门控的现场数据回流，加上与当前技能对齐的短程RL，比原配方直接继续100任务长跑更值得优先验证。这是待验证假设，不承诺最终SR/Q提升。

选择一条主线：已有TRAIN rollout → 分用途验真/清洗 → 结果头与高层恢复SFT、低层有效片段FM-SFT → 固定小开发集验收 → 新鲜短技能rollout的共享PPO → 再回流。保留G0.5/FM低层与MEM-Lite分层，不重新训练三个任务组模型，也不立即重写为另一套完整offline RL。

- **先补反馈和学习信号，再增加更新强度。** 不能把“调LR、加epoch”和“正确识别已经握住工具”混成同一个问题。
- **失败任务也能贡献数据，但用途不同。** 失败状态教结果头识别；真正纠正过来的片段教恢复；局部正确动作教FM。整条失败不能变成整条正向模仿。
- RECAP将示范、自主经验与专家纠正结合，并用value/advantage conditioning提取策略；它不是“失败轨迹全做普通BC”。本方案先借鉴数据闭环，暂不声称复现RECAP。[原论文](https://arxiv.org/html/2511.14759v1)
- 现有候选不是保存了完整随机去噪链/old-logp的旧PPO batch；不能把已执行动作重新算一个logp就当原采样似然。离线数据先走SFT，PPO仍用当前冻结版本新采样的数据。[ReinFlow原论文](https://arxiv.org/abs/2505.22094)

### 2. 可用数据、缺口与四种去向

10/09 11:02审计时有238份候选ZIP，**不是238条恢复成功，也不是130万控制步全部有RGB**。原收集器保存事件前后局部窗口、每16控制步一个三相机RGB锚点、真实执行raw23动作、61维本体状态、task/instance/episode/intent/policy版本及物理记录。数值日志中没有留存图像的其它时段不能事后“补成视觉轨迹”。旧ZIP保持不可变，验真标签写版本化sidecar/manifest；当前全部候选默认仍不可BC。

| 数据池 | 可接收的证据 | 训练用途 | 不允许的转换 |
| --- | --- | --- | --- |
| `D_outcome` | 正常推进、局部成功、可验证抓空/脱手/错误对象等；观察不足单列 | 结果分类、置信度校准、停滞提示 | 超时/无Q增长直接标FAILED；缺标签伪装成UNKNOWN真值 |
| `D_plan` | 同一实际状态下，后续经过执行验证的继续/重试/重规划意图；保留正确专家规划锚点 | 高层decision/intent/memory的CE | 检测到失败就凭想象填一个“正确恢复意图”；将旧错误动作配给新意图 |
| `D_action_good` | 同一技能/对象/手臂条件下确实有效且质量合格的动作段，含整任务失败中的局部成功 | 低层FM-SFT；专家锚定样本 | Q偶然上升、闭夹爪、手已握物体的一张图，直接当完整好动作段 |
| `D_candidate` | 证据缺失/矛盾、未恢复的失败、等待人审的片段 | 诊断、补采队列；不进actor正向BC | 自动晋级expert/recovery、用重复窗口冒充更多独立事件 |

`D_outcome`使用已有`IN_PROGRESS/SUCCEEDED/FAILED/UNKNOWN`枚举。UNKNOWN是证据确实不足时的弃权标签；没有完成标注的样本用mask=false隔离。`stalled`为风险提示，不等于物理FAILED。局部SUCCEEDED与官方整个任务成功分开存储。

训练样本以真实RGB锚点为准，不将同一张图复制成16个独立视觉样本；结果标签与该观察截点绑定，动作目标从同一截点之后的实际执行开始。后继状态/未来确认只能用于审核与决定片段是否可收，不能把“下一动作抓住了”回填为执行前已经SUCCEEDED。

抽取有三层门：

1. **全量结构门：** hash/解码、实际动作确认、23↔27有效维映射、真实步时钟、RGB锚点、before/after状态、task/episode/手臂/对象身份及版本一致；不跨reset拼窗。不能将未执行的后16预测步当动作真值。32步FM目标只能来自连续真实执行且意图兼容的未来32步；短尾或跨技能段先排除，除非独立验证了目标mask合同。
2. **物理/语义门：** 以稳定抓持、接触/状态关系、对象运动与技能结束条件联合验真，记录判据版本和证据时刻；仅Q增减不能证明动作因果。正例必须与实际执行技能一致。错误NAV下意外抓到东西不直接算NAV正例；如要事后更正为GRASP，需单独的实际动作语义核验与来源标签。
3. **人工分层门：** 首批至少60个候选窗口（不足则全审），覆盖技能、成功/失败/歧义、不同task/实例/策略版本；首批所有拟接纳的恢复正例逐条看原图/视频。发现关键误标则撤回相同规则生成的相关批次、修规则并重审，不靠总体准确率掩盖false-success。最终清单报告真实可用数、拒绝数、缺失类与审核范围，不保证238份都能用。

先按原始`task/scene/instance/episode-root`分组，再切窗口；同一状态分叉、重试和近重复样本不能跨split。原留出/public/开发过的public301不回灌。固定TRAIN-dev只做配对开发回归；旧SFT或RL见过的实例不能宣称“从未见过”。真正泛化结论另需未用于新数据训练/奖励调试的实例或任务，并明确旧SFT暴露情况。

### 3. 恢复数据从哪里来

按成本排序：

1. **现有轨迹中的自然纠正。** 找到“可验证失败→实际调整→同一对象/目标重新达成→短时间保持”的完整链；只复现原动作，不能补写不存在的纠正。一次握住物体的照片不够证明之前失败、之后恢复。
2. **正常示范作锚点。** 复用已验专家数据中的正确技能/交接；不能把不同状态的专家动作直接贴到失败现场，也不能将演示标注区间结束当成功真值。
3. **从失败附近分叉补采。** 有合法完整状态恢复时，绑定物理状态/机器人控制器/资产/RNG/传感器验收，再在同一失败起点试少量候选恢复意图或不同采样seed，**只接纳真实恢复并保持目标的分支**。首轮每起点最多3分支，全部成败保留。恢复不可用时，改用经过验真的示范前缀/重新rollout到该状态，不能用RGB＋关节位置伪造完整世界恢复。
4. 若上述没有正确续段，进入专家纠正需求队列；VLM可以提议候选子目标，但未经过真实执行验证不能当专家。遥操作/新外部标注资源需另行协调。DART只有在存在能纠正扰动的专家及验证过的状态恢复时再启用，随机给当前弱策略加噪不叫DART。

首先用已有候选回答“能提取多少真正有用样本”，不先承诺收集数小时就够，也不再为了凑时长连续生成大量同一种无进展轨迹。

后续收集器需要补覆盖：事件相关对象取当前意图目标/手臂/所用工具与任务对象的并集，不只盯最终BDDL目标，避免漏掉扫帚等工具的抓取/脱手；稳定抓持按同一对象、同一手臂连续确认，不能将两手零散持物拼成一次成功。除了失败事件，还抽取少量正常推进和正确交接窗口，防止训练集只剩“卡住”。候选后段延长到可验证局部结果或显式采集上限；到上限仍无证据的只作截断，不伪标恢复。新RGB/动作按真实chunk锚点保存并绑定存储配额，不能假定无限录全程没有性能/磁盘代价。

### 4. 高层：先让它知道执行结果，再教恢复决策

复用`src/g05/models/g05/helpers/outcome_head.py`及`G05PolicyMEMLitePlannerOutcome`。已有头是因果context表示上的四分类器；当前planner-only根本不训练/启用它。训练profile、输入schema和runtime必须一起版本化，不能只把`outcome_ready`改true或去掉UNKNOWN格式保护。

**部署输入设计：** 当前RGB/本体状态、先前已发技能、可部署短历史证据、当前技能持续控制步数、连续重复规划次数、尝试编号、最近可信度校准后的预测结果。后四项不是仿真真值。重复发布同一bundle不再从记忆里“消失”：保留压缩摘要与计数，不把同一句复制几十遍。失败证据只记到当下可知的时刻；未来帧只可用于离线审核，不能提前作为模型输入或当下成功标签。

首版保留现有单帧视觉骨干/高层规划节奏；在每次既有高层检查时复用因果context特征，配最近少量检查点的缓存特征/本体变化，训练小型时序适配器后接已有结果头。历史只用当前时刻以前的信息，明确最大窗口/缺失mask；不新增一套大VLM、不每个控制步重新跑高层。cache按env/episode/模型版本隔离和失效。若实现无法复用现有prefill，必须实测额外开销再验收，不能承诺零成本。

反馈预测经置信度/连续确认门进入planner；不确定则UNKNOWN，不能仅因超时自动“已完成”或一律松夹爪。planner再决定`EXECUTE/RETRY/REPLAN`及既有registry中的下一技能；STOP不直接作为官方成功。预测状态写入`estimated_execution_state`等有来源/置信度的字段，不冒充`verified_world_facts`。并行双臂bundle须按技能成员/目标对象追踪结果，全bundle聚合规则显式：一只手抓住不等于两只手任务全成功。

训练顺序：

- H0：冻结高层骨干，先训练/校准结果头与时序适配器；已完成局部动作与仍在尝试的困难边界须覆盖，结果只从答案前context提取，防teacher-forcing标签泄漏。
- H1：用正确规划锚点＋验真的恢复分支训练高层。复用既有可审计trainability组，小样本先小步更新，不直接重开100任务全量SFT。`L_high = L_decision/intent/memory_CE + λ_outcome L_outcome_CE`；H0只更新头/适配器，H1按明确名单允许高层参数与头更新，**不会更新低层动作专家**。
- H1输入要见到结果头真实的错误/UNKNOWN：按原始实例分组产生out-of-fold预测或独立冻结结果头预测，不能训练时全用oracle反馈、部署却突然换成噪声预测。重新校准必须与最终高层/头版本绑定；高层参数变化会使旧缓存/旧校准过期。
- 只有通过留出类别校准、false-success审核及真实闭环，才签发outcome readiness。数据不足的技能保持UNKNOWN。当前固定UNKNOWN常量是旧安全合同，不是待删的无用限制。

### 5. 低层：正确片段SFT＋对齐当前意图的共享RL

**L0先做小规模有效片段FM-SFT。** 起点优先保留可追溯SFT高48045/低98414；当前RL checkpoint另存为候选，不因步数新就认定更优。原始专家动作约70%、新验真局部/恢复片段约30%作为初始采样配额（非最优定理）；新数据缺失时不补假样本，限制单trajectory/同一重复片段占比。task与技能分层抽样，仍从100任务专家池取保真锚点，不只重复几个成功实例。

低层先只更新既有action expert、保持VLM与高层冻结，使收益来源清楚；保持raw23↔model27、原归一化、预测32/执行16、动作起点0及真实基座/躯干。`L_low = L_FM(expert anchors) + λ_new L_FM(verified segments)`按采样/样本权重实现且不重复加权。错误高层意图不能配正确专家动作做正向监督。若意图表述变更须提供等价schema或另做严格对齐适配，不能擅改动作/技能含义。

**L1再从新鲜短技能数据做共享PPO。** 高层与结果头在这一小轮内冻结，先隔离低层可学性；8卡仍同步同一动作专家/critic/Adam，不训8套模型再平均。

- 先8个TRAIN任务覆盖至少4类机制：导航/到达交互区、单/双臂抓取与重新抓取、持物移动/放置、关节开合或接触操作。具体task/instance/seed必须依据实际可恢复状态与数据覆盖生成manifest，**本设计未伪造已锁定任务表**。以技能类而非每任务手写一套算法；100任务的不同对象和工具共享同一接口。
- 近技能合法起点课程，每段先限512–1024真实控制步（约17–34秒仿真时间，非墙钟），重复面对能获得信号的接触阶段。保留少量原始reset的短闭环检验接口，但短budget未成功不能记整任务FAILED；最终完整SR需官方完整预算。
- 通用奖励由`active_skill + target/arm + physical transition`决定：GRASP奖励指定对象稳定抓持；PLACE奖励正确关系、释放及保持；OPEN奖励目标关节/可用开度；运输约束保持所需承载物。导航距离/朝向只作有界提示，几何接近不直接证明可抓/已到交互位。扫地的奖励输入应包含当前broom目标，不能只看最终floor literal。
- 形式为`r = w_local * verified_local_event + w_task * official_task_progress + [γ^Δ Φ(s_next,g) - Φ(s,g)] - verified_damage_cost`。势能只在固定局部目标g内差分、使用真实消费步数折扣，技能交接/终止正确清零或bootstrap，不跨不同目标无脑相减。系数按技能族统一、量级有界且另行小测校准；不声称加入局部奖励必然保留原全任务最优策略。
- 防反复抓放刷分、防只握工具不做任务、防目标已成立仍领一次次奖励；正确技能切换后要检验原有有效进展是否保留。不可把暂时打开最终应关闭的冰箱等合法中间步骤粗暴判为回退；按任务语义适用性给保持约束。
- 更换奖励/目标后重新训练或明确重置critic，不能直接沿用旧value尺度当可靠优势。先修`post_update/value_loss`采集位置，补优化前后value、return分布、explained variance（方差近零则NA）、advantage分布、逐skill奖励占比/局部成功、真实控制步数/小时与空转比例。

**L2最后校准力度。** 奖励/数据/共享更新门通过后，在同一配方与固定开发条件下先试actor `1e-7 → 2e-7`，只有受控且有用才考虑`3e-7`；critic先保留`1e-4`但以新目标的实测诊断校准，不按卡数放大。FM10、预测32/执行16、探索std先固定，保留全局及逐组KL/clip拒绝与完整actor/Adam共同回退。`1 epoch → 2 epochs`作为另一项后继单变量，不同时叠加；当前shared update不是改个epoch字段就已具备多轮复用，须实现同一old-policy样本、多轮一致重算/全局门控及相应测试。GAE跨度/λ若仍不足再单独测，先靠近程可信奖励缩短信用链。

离线SFT与PPO首版分段交替；切换前提交checkpoint并丢弃未提交的旧on-policy buffer，新轮重新采样，避免一次SFT后用旧rollout冒充未变策略。旧失败样本不进入普通正向FM loss，也不在不可靠critic上立即做exp(advantage)加权。后续若value已在留出上有区分度，可单独研究AWAC式加权回归或RECAP式advantage conditioning；它们与当前过滤SFT＋PPO不是同一算法。[AWAC原论文](https://arxiv.org/abs/2006.09359)

### 6. 先验什么、何时停、哪些数能叫效果

以下是**下一轮建议上限，尚未执行的运行票**。不追加当前24h作业。首次GPU验收/采集/训练启动之前须冻结code commit、父权重SHA、数据清单与split、合法起点、task/instance/seed、奖励版本、owner与STOP条件；缺项就不启动GPU。

| 阶段 | 主问题/交付 | 建议上限与停止条件 |
| --- | --- | --- |
| P0现有数据盘点 | 对已封存候选全量结构校验、分层人审，四数据池与缺失报告 | 0训练GPU；先冻结现有一批，不无限等待候选增加；无合格恢复就如实为0 |
| P1工程小验 | 因果反馈、技能奖励、状态恢复/前缀、动作/跨env/双臂隔离 | 最多1GPU/90分钟/4096实际控制步/8次reset，先到为止；任何oracle泄漏/串任务/错误成功即停 |
| P2数据反馈小训 | H0/H1与L0各独立产出，可比较而非一口气混在一起 | 每条线最多1000优化步、合格新增事件等效5遍或4h墙钟，先到为止；微batch显存先验，GPU数按已验环境锁定，合计不超10383的8卡；小数据不靠反复复制凑步 |
| P3短技能RL | 验证新奖励是否带来固定技能成功率改善 | 一个主候选，至多30次共享更新/约25万实际控制步/4h先到为止；前2轮工程门；无可信信号或重复同故障则停，不自动续24h |
| P4更新强度 | 固定新配方下比较1e-7与2e-7，不重扫多维超参 | 仅在P3门通过后，至多一对同预算短对照；不因有空卡无限网格搜索 |

P2的“等效5遍”按合格新增事件抽样累计量定义，不能用相邻帧膨胀epoch；原始专家按预定70/30比例作为锚点另记用量。上述步数/时间只是有限试验预算，不是训练到这些数就一定足够。

### 实现边界与验收要求

- PyTorch DDP可同步副本梯度，但不会自动切数据，也不会替我们同步业务层KL回退/采样版本。[安装版本对应的PyTorch 2.7 DDP文档](https://docs.pytorch.org/docs/2.7/generated/torch.nn.parallel.DistributedDataParallel.html)
- 当前自定义FM loss直接调用action expert的embed/decode等方法且含多步采样，不能机械包一层DDP后默认全部正确。首版倾向明确在`update`的本地backward完成后、clip/step之前对固定参数顺序进行分桶all-reduce；或先把完整loss重构为标准forward再用DDP。无论哪种，需证明与单进程同一全局batch的梯度/更新一致，并测试12/13任务组、短尾/零adv、全局KL回退、故障超时及resume。
- 先核old-logp重算在**任何更新前**与采样一致，再做多卡更新；B1与batch4的固定噪声误差并非RL似然等价证据。当前评测候选完整32步最大误差门仍失败（最大落在不执行的后16步真实维度），不能拿未执行动作差异小/成功起进程来替代PPO正确性检验。
- 不允许每卡独立推进多次optimizer.step再偶尔平均模型，那会使收集策略和更新策略发生分叉。第一版不引入异步陈旧策略；若慢rank等待/重置成本明显，再单独衡量固定版本集中learner/collector调度，不先叠加多个算法改变。
- 初始建议共享SFT低98414＋冻结高48045，重新建立一套RL optimizer/critic；旧8专家保存，不直接平均。也可在有证据的前提下选择某**一份**既有RL checkpoint作为全rank公共起点，但目前没有8专家中的最优可比结果。不用再跑一套公共baseline。
- 本轮Actor LR已选修复canary可接受的`1e-7`、critic`1e-4`，不因卡数8就乘8；全局/逐组KL门控制接受或共同回退，具体其余参数见本节顶部。同步8卡不是稀疏成功信号的解法：没出现或未被可靠奖励的“没抓住→松开→重抓”，不能期待只靠合并梯度学会。

| --- | --- | --- |
| πRL/ReinFlow＋PPO | 主候选；优先审计一种随机FM采样实现与其概率计算，实际RL更新动作专家 | rollout昂贵；需critic、正确轨迹概率和稳定探索；不能把FM loss直接叫log-prob |
| DSRL噪声空间RL | 低成本备选；共享小策略根据任务/技能/观察选择FM初始噪声，基座冻结 | 更受基座动作分布限制；若基座根本抓不稳，换噪声未必创造所缺技能。π0参考实现不是G0.5适配完成。[文档](https://rlinf.readthedocs.io/en/latest/rst_source/examples/embodied/dsrl.html) |
| FPO | 后备；不直接计算动作似然的flow-policy优化思路 | 需验证近似目标、梯度方差和大VLA训练成本，当前不另起完整实验线。[原项目](https://flowreinforce.github.io/) |
| SAC-Flow | 后备；若环境采样成本主导，再评估off-policy复用经验 | 公开示例和模型结构不等于现有G0.5；critic/速度重参数化接入可能明显增加改造量。[官方文档](https://rlinf.readthedocs.io/en/latest/rst_source/examples/embodied/sac_flow.html) |

ReinFlow作者明确将其定位为后训练，提醒SFT能力影响RL难度。我们当前A3完整任务失败、正确GRASP也不足，**不能期望从几乎无成功信号的长任务稀疏奖励中自动学好一切**。短技能课程、真实演示起点、可信结果奖励和必要BC改进是学习条件，不是针对某个任务作弊。[作者限制说明](https://github.com/ReinFlow/ReinFlow#-limitation-and-caveats)

RL起点也不能只按“最新checkpoint”选择：先依据已有证据和一次有界检查确认其动作约定正确、必要基础技能尚在。若某个新SFT分支已退化，先解决/回退该退化，不把RL结果与换基座、修bug、换观察格式的收益混在一起；不为这个门槛另开无限基线评测。

## 2. 哪些组件必须通用

### 共享条件化策略

输入沿用当前允许的图像历史、本体状态、任务文本、当前技能/对象/手臂、可部署记忆/反馈。首阶段高层固定，只更新同一个跨技能FM低层；不存在“盘子网络、柜门网络、垃圾桶网络”三套默认分叉。

高层选择错误和低层执行失败分开归因。低层接入稳定后，才考虑在技能边界对高层做独立return/advantage优化或用真实纠正更新规划；不能声称连续FM梯度穿过生成文本。扩到50任务时统一采样/条件接口，按任务或技能均衡并保留未训练类型验证。

### 共享奖励事实层

统一`task_goal / active_skill / transition / termination / validity`接口：

- 整任务最终成功以官方判定为锚；不替换比赛成功规则。
- 从任务定义及已审计物理谓词生成目标进展/阶段完成事实，正确处理AND/OR、目标对象和部件绑定。不能只数任意成立谓词，也不能把所有任务假设成线性技能序列。
- 已校准的技能交接条件可做训练辅助：抓稳、有效放置、开合达到可用状态等；未知/未校准项不伪标。开门谓词成立不自动等于足够让后续物体通过。
- 通用失败事件覆盖抓错、脱手、承载物滑落、非计划碰撞、目标条件丢失；它们的适用性/原因要可验证。掉落只是其中一类。
- 进展 shaping 必须有防投机测试：反复拿起放下刷分、开关同一门刷分、原地保持稳定却不做任务、提前终止。若采用势函数差分，折扣和terminal处理需与RL目标一致；不宣称随手加dense reward能保持最优策略。
- 多任务按有效目标数量/尺度做明确归一化，避免长任务或某一密集技能垄断更新；奖励系数按统一类型定义，不按对象ID写例外。

仿真真值只进入训练reward/可选训练critic和诊断，部署actor/高层不得读取。结果头是可部署的观测预测器，不能与真值奖励provider混为一谈；用预测结果当奖励前需要独立校准和防自我奖励。

### 通用时间与轨迹格式

统一记录两种时间：真实环境动作步，以及FM去噪步。当前生成32步、执行16步；记录实际消费长度、完整采样latent/旧策略概率、有效23维mask、done与time-limit、状态/目标条件和policy版本。

不能把没有执行的16步当作真实环境transition；也不能未经概率推导就删掉去噪链一部分log-prob项。必须明确优化的是完整随机采样链还是实际动作的概率代理，并做old/new-policy一致性和固定输入复现检查。夹爪/底盘真实维度不可误mask。

按真实消费长度处理奖励累积、折扣、bootstrap与技能边界。自动reset后不得把另一episode第一帧当上一episode的后继；长任务只在日志存在的真实transition上分配信用。

## 3. 长任务怎么学，但不变成50个手写方案

使用一套**由短技能到短链再到完整任务的课程**，起点来自train实例的真实演示/成功轨迹且可核验复放，逐渐增加自由运行长度。起点抽样按技能/阶段覆盖，不为每个物体手写控制。

首批代表类型至少包含抓取/释放、接触开合、导航/运输、放置或双臂配合。端盘用于暴露承载稳定性，不享有特殊算法/专属奖励分支。小规模阶段先验证2–3种不同机制，再按预先声明预算扩充类型；最终在未用于奖励调试的任务/实例上验证迁移，而不是同一盘子换几个seed。

初轮高层固定可以明确“RL是否改进低层”；随后接回MEM-Lite自动高层/结果反馈检查是否保留收益。L1局部成功、L2诊断反馈、L3完整自主SR分别报告。课程起点和演示前缀绝不算自主任务成绩。

## 4. 基础设施优先复用，但先查兼容性

RLinf已有BEHAVIOR 50任务、R1Pro 23维动作、OpenVLA-OFT和π0/π0.5的PPO示例；它是很相关的接入候选，**并不直接支持我们的G0.5＋MEM-Lite实现**。其页面仍使用2025实例/IsaacSim4.5，并提示部分模型训练成功率可能维持0；先核查固定commit与问题状态、2026资产/机器人/评测定义，不能直接安装后宣布可用。[BEHAVIOR官方接入说明](https://rlinf.readthedocs.io/en/latest/rst_source/examples/embodied/behavior.html)

该项目也发布BEHAVIOR rollout优化，涉及按需观察和多进程流水。其25×结果来自特定硬件/配置，不是我们四张A100的预期倍率。我们六帧历史、物理诊断和官方判据所需的观测不能被优化掉，画面一致性与实际时钟必须复测；暂不改正在运行的模拟器。[系统优化记录](https://rlinf.readthedocs.io/en/latest/rst_source/resources/blog/behavior_system_optimization.html)

## 5. 三人交付接口

| 人 | 独立负责 | 交给另外两人的边界 |
| --- | --- | --- |
| A | G0.5/FM训练与采样适配、action mask/归一化、专家参数与旧权重保真 | 可复现`sample/score/update`接口、训练参数清单、实际消费动作映射；不负责手写每任务奖励 |
| B | 多任务目标/技能协议、可信结果标签与预测、记忆/高层阶段 | reward/feedback所需的统一语义、validity和边界；部署输入白名单；不在actor中塞oracle |
| C | PPO/rollout/critic接线、统一reward provider、课程/reset、性能和跨任务评测 | 用A/B固定接口完成一个候选通路；按少量异质任务报告成功与失败，不另造端盘专用模型 |

A/C都涉及模型时，A拥有模型文件，C拥有trainer/环境；通过分支和接口提交交接，不在同一目录并发覆盖。所有人先pull最新main/自己的分支，完成后push代码及轻量结论。

## 6. 有界验收，避免研究无限膨胀

1. **适配门**：一次CPU/小GPU检查＋少量真实transition，证明概率/采样、梯度、奖励、mask、done/bootstrap正确。
2. **接入门**：首轮上限10,000真实控制或2小时墙钟，先到为止；只回答能否可靠收集和学习，不声称通用性。
3. **方法门**：团队先冻结少量异质任务、train/eval分割、两组配对seed和总预算；只跑一个主候选。汇报跨技能进展、局部/完整成功、退化和单位真实交互成本，不只reward涨没涨。
4. **选择门**：相同故障无新解释就停重复试验；主候选因明确成本/技术约束不可用时，才转DSRL等下一候选，不把四算法全做一遍。
5. **规模门**：方法有跨类型证据、基础SFT够用、奖励与数据扩展可行、存储/吞吐可预算、checkpoint恢复可靠，才申请50任务正式训练。

当前尚无证据可称任何候选是“50任务最优RL方案”。这里明确的是一条与现有FM匹配、可验证且可停手的主路线，以及接口/奖励/评估的通用性要求。
