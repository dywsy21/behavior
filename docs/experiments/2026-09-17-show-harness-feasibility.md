# H-01：Show-Harness能否用于我们的BEHAVIOR项目

日期：2026-09-17（北京时间）。负责人：Codex。状态：**研究完成；实施、数据构造、模型调用与仿真均未启动**。

## 结论

值得开一条独立的语义微动作路线，先用冻结的强VLM检验接口，再决定是否蒸馏/微调本地小模型。保留现有FM作为对照、保留高层任务记忆与低层控制分离；不预设新路线必胜，不据桌面任务结果直接替换全任务模型。

这条路线最直接检验的是：**当“下一小步做什么”由VLM决定、机械执行由可检查的控制器完成时，能否减少现有低层的条件不服从与抓取启动状态失配？** 它不能自动解决视觉定位错误、接触动力学、稳定运输或长任务完成反馈。

## 一手证据及其边界

- [Show-Harness论文](https://arxiv.org/pdf/2609.10522)：核心是语义微动作和确定性执行器，有零样本强VLM及小VLM微调两种模式。表2在十个物体—容器任务上报告ZS/FT/π0.5分别89%/86%/39%；每任务10次。微调比较使用其接口采集的同源演示，不是本项目R1Pro或正式BEHAVIOR全任务对照。因此不能把该差距当作我们能获得的收益。
- 只读审查官方[代码commit 137d5718c3b7af0150764d8f9beeb252c9f2794a](https://github.com/showlab/Show-Harness/tree/137d5718c3b7af0150764d8f9beeb252c9f2794a)。[FT接口文档](https://github.com/showlab/Show-Harness/blob/137d5718c3b7af0150764d8f9beeb252c9f2794a/docs/finetuned.md)显示发布adapter有固定prompt/视角约定，AgileX路径还交换前后token；不能把其权重直接当R1Pro已适配模型。小模型默认不带完整规划器；[训练管线](https://github.com/showlab/Show-Harness/tree/137d5718c3b7af0150764d8f9beeb252c9f2794a/train)可作工具参考，不安装进当前共享环境。
- [恢复插件](https://github.com/showlab/Show-Harness/blob/137d5718c3b7af0150764d8f9beeb252c9f2794a/plugins/recovery/plugin.py)主要从实测夹爪宽度判断空夹/丢失；[本体插件](https://github.com/showlab/Show-Harness/blob/137d5718c3b7af0150764d8f9beeb252c9f2794a/plugins/proprioception/plugin.py)使用实测位移与桌面高度。迁移时须重新标定，并将夹住物体、夹住正确物体、稳定搬运三个命题分开；不能照搬固定桌面高度到整个房屋。
- [Anthropic的机器人实测](https://www.anthropic.com/research/claude-plays-robotics)提供反例：其LIBERO低层直接控制完整成功率很低，且让agent频繁覆盖较好VLA的动作也可能变差。接口、模型和任务不同，不能和Show-Harness直接比百分比；共同提醒是“强语言推理”并不保证精确操控。
- “BEHAVIOR上没有agentic机器人工作”不成立：[ASPIRE](https://arxiv.org/html/2607.00272v1)已研究代码式agent在两个导航并抓取任务上的执行；[Semantic Handoff](https://arxiv.org/html/2607.06256v1)研究agent编排π0.5技能和视觉验证。二者不等于Show-Harness微动作路线的正式全赛道提交。本次未核实到该微动作接口的正式榜单成绩，不作“首个”宣称。
- [去年冠军](https://arxiv.org/html/2512.06951v2)的System2是阶段预测/跟踪后反馈给FM，并非通用VLM逐步操作机器人；与本候选不应混称。

## 1. 是否需要微调

### 第一阶段：不微调，但要实现机器人适配

先选择一个固定版本的强多模态模型，使用同一套合法观测和可审计微动作工具。需要开发的是R1Pro控制接口、标定、反馈与计时，不是先训练网络。这样才能区分“模型不会操控”和“控制器/坐标映射错了”。

三个角色仍分开：

1. **任务层**：维护目标、计划、已观测事实和不确定性。可复用MEM-Lite的数据结构，但不能假定当前B-final/UNKNOWN_ONLY已经具备可靠反馈。
2. **局部VLM控制层**：从当前图像、合法本体、当前子目标和近期执行结果，选择一次有限微动作。
3. **机械执行层**：把微动作转换成连续、限速的控制序列；回报实际位移、到达误差、不可达和限幅情况。确定性是命令解释确定，不是保证物理动作一定成功。

本项目建议的工具接口（提案，不是论文原版或已实现API）：

| 工具类别 | 例子 | 必须明确的语义 |
| --- | --- | --- |
| 单臂末端 | `ARM_STEP(right, left, fine)`、`ARM_ROTATE(left, yaw, clockwise)` | 手臂身份、参考坐标系、预设步长、姿态与控制时长 |
| 夹爪 | `GRIPPER_CLOSE(right)`、`GRIPPER_OPEN(left)` | 只开合，不自动寻找/抓住物体；与现有高层GRASP技能区分 |
| 底盘 | `BASE_STEP(forward, coarse)`、`BASE_TURN(left, fine)` | 本体坐标、有限时间、停下与避障，不使用全局真值位姿 |
| 躯干 | `TORSO_STEP(up, fine)` | 四关节协调由运动学和可达性约束求解，不把一个关节当整段躯干 |
| 双臂/保持 | 同时提交左右臂微动作，其余显式HOLD | 统一时钟、互碰检查；HOLD是保留目标姿态，不是把关节置零 |

优先保持现有R1Pro物理/控制配置，在policy侧用FK/IK生成原23维命令，从而减少对照的混杂。如果确需换成官方支持的IK controller，另立配置/对照并固定新的action_dim，不能继续假装是原23维。

参考系必须随头部/腕部/底盘运动正确更新；标注视图及方向箭头可由标定产生。接触前缩小步长，旋转、移动底盘/躯干、夹爪状态变化后重看；远离接触才考虑短串行动作。高频轨迹跟踪仍由传统控制器承担。房间探索可由合法RGB-D/里程计构建在线地图，不能用隐藏全屋图。

### 第二阶段：本地部署才优先考虑小VLM微调

- 原始2B–4B指令VLM的空间控制未必够好。强VLM在正确接口下有效，而本地模型明显落后时，微调有明确目的：学会本视角下的方向、选择步长/手臂、何时关闭夹爪和如何纠偏。
- 可试公开的机器人语义动作adapter作为初始化，但要标为“已有机器人训练、无新增BEHAVIOR训练”，不是纯通用模型零样本；先解决其相机/方向/prompt契约。
- 不把G0.5的ActionCodec AR当同一方法。现有AR预测未来动作编码；候选预测可解释微动作、执行后重新看，训练目标和误差传播不同。
- 初轮SFT用短动作JSON/native词表CE即可，不训练大FM专家，不要求长CoT。语言解释可作审计辅助，不能作为完成真值或将未经校验的解释当监督。
- 当前FM保留。后续若混合两路，必须显式交接控制权并重置控制器目标，不能平均两路动作，也不能预设agent逐步覆盖FM会更好。

## 2. 微调数据怎么来

建议次序：**旧演示可验证转换 → 在真实agent到达状态下补纠偏/接管 → 少量跨场景扩大**。由队友一负责正式数据构造/发布，Codex提供动作契约与模型检查；本次不代替其启动新采集。

### A. 现有官方演示：自动几何标注，但不是直接改标签

输入是已有同步图像、本体和raw23动作。先从机器人字段元数据解析关节/末端/相机关系，必要时用FK计算末端位置姿态，再在**同一参考系**计算一段运动的平移、旋转、夹爪事件、底盘和躯干变化，匹配候选微动作。

关键限制：

- 原动作含绝对关节目标，不能对相邻action数组直接取符号当“手往左”。要区分目标与实际运动、基座运动与手臂运动；旋转用SE(3)/四元数关系，不直接减四元数。
- 一次原运动可能多轴/双臂同时发生，不能只保留最大轴后声称完整等价。接口需支持受限组合，或只保留可重放验证的子集并报告丢弃率。
- 把一个斜向运动拆为两步时，中间图像必须来自重新执行后的真实状态，不能复用原轨迹不存在的中间帧。
- 每个候选标签在原起点由**新执行器重放**，检查实际终点、碰撞/接触、夹持和后继可执行性。偏差过大的片段不作BC正样本，保留诊断。
- 训练标签可利用未来运动确认，但输入只能包含当时及以前的观测；不能把未来状态、最终结果或GT物体位姿放进prompt。

这能减少人工逐帧写微动作的成本，但转换成功率、可保留规模和重放成本尚未测量。不能承诺现有950训练episode全部可直接复用。

### B. 强VLM rollout + 人工接管：补真实失配状态

强VLM先通过新接口操作，在其**实际到达的状态**由人或受控teacher接管。保存纠正动作及执行结果，而不是把同时间戳的原专家动作拼上去。优先补：目标看见但够不到、抓空、抓错、遮挡、开门未到位、运输掉落、双臂互阻等跨任务问题。

正向BC使用审核通过的动作/纠正段；错误动作保留为失败示例、反馈标签或未来RL资料，不因整条轨迹最终成功就将此前所有错误动作视为正确。API teacher的数据使用条款和费用另行核对。

### C. 自监督能教什么，不能教什么

由实际执行记录可自监督学习“微动作→位移/视觉变化”、可达性和动作结果预测，也可反推已发生的微动作。它不能凭空提供“为了当前任务下一步应做什么”的专家标签。任务条件化策略仍需要专家演示、teacher纠正、经过验证的成功经验，或后续结果驱动RL。

仿真特权状态可做离线标签/奖励和质量审查，但学生输入必须保持合法、可观测；不可见的目标身份或隐藏状态应标UNKNOWN，避免让学生拟合在输入中不可辨别的答案。

### 最小样本契约

每个decision至少保留：`source_episode/group/task/instance/seed`、执行前多视角图像和本体、当时子目标/参考系、历史实际动作、选定微动作和粒度/持续控制步数、raw23执行序列、执行后观测、执行器回执、结果标签的来源及可观测性mask、controller/prompt/校准版本。

策略训练区与特权审核区物理分离；按来源实例/原episode分组切分，所有重放/分支继承同组。保留原逐task5%和public_test不回灌。人工抽查需覆盖方向/视角/手臂/旋转/底盘/躯干/空夹/掉落，而不仅看正常抓取；缺失失败类别如实标缺。

## 3. 预期效果及风险

以下是工程判断，**不是已经测得的成功率**。

| 能力 | 我的预期 | 仍可能失败在哪里 |
| --- | --- | --- |
| 微动作服从/可解释性 | 最有希望改善，易定位命令与实际运动差异 | VLM选错方向、相机坐标错、IK不可达或碰撞限幅 |
| 意图和对象绑定 | 显式目标与逐步视觉检查有帮助 | 确定性执行器不识别目标，模型仍可能抓错相似物体 |
| 新位置的抓取、纠偏、空夹恢复 | 值得优先测，比只重复干净演示更贴近现有失败 | 腕视角遮挡、深度噪声、夹爪姿态与接触不准 |
| 底盘—抓取交接 | 可明确检查可达性再切换 | “已经看见”不等于能抓，未知障碍与运动学耦合仍在 |
| 稳定端盘、接触开合、精细双臂动作 | 不能预期自动解决，可能更慢/更顿 | 需要连续轨迹、接触反馈与姿态保持；此处仍可能需要FM/通用RL |
| 完整长任务 | 最不确定，不外推论文百分比 | 多阶段误差累积、假完成、API调用数、控制步预算与恢复成本 |

项目依据：A4在448步演示前缀后的局部抓取取得过一次成功，但自主radio 301/302/303均0/3，导航后持续正确GRASP也未抓住。见现有`docs/experiments/2026-09-13-a4-training-effectiveness.md`及`2026-09-13-a4-radio-full-eval.md`（实验分支）。这支持检查真实交接状态和执行接口，不证明所有问题只有一个根因。

若十段条件成功率都为90%，无恢复整链只有约35%；这是误差累积示例，不是本方法预测。需要同时统计实际微动作到达、局部技能、交接、完整成功与Q-score。

速度要分开算：VLM决策频率、控制器跟踪频率、模拟器步进FPS、全回合墙钟。若500次调用每次2秒，仅调用即约17分钟，这是示意预算而非实测。同步仿真可在等待回复时不推进物理，但这不消除墙钟/API成本，更不是实时机器人性能。小模型部署的收益是潜在延迟降低，不能照搬论文GPU延迟数字。暂不承诺比现有FM更快。

夹爪宽度只能作空夹/受阻的证据，不能证明拿对目标；R1Pro当前assisted模式还需单独标定。应融合合法多视角、夹爪读数及微小抬起后的共同运动来估计持有，并允许UNKNOWN。盘子仍在手里而食物掉落，要跟踪承载对象关系，不能只看夹爪。

## 有界验证提案：尚未批准/登记为运行

H-01只交付研究。以下是下一步建议，不是新训练排队，也不改变两位队友当前任务。

1. **H-02接口门**：Codex负责。0神经训练；先在train开发状态下测全部动作的方向、幅度、HOLD、控制时钟、FK/IK与限幅。对照原R1Pro配置并由人用同接口完成基本局部操作。接口门不通过就修接口，不消耗模型训练来掩盖它。
2. **H-03零样本门**：先固定一个强VLM，三类异质局部问题各四个预注册起点，共12个episode/路线，冻结FM对照和微动作路线共24个；每回合共同1536物理控制步上限，候选另加60次VLM/15分钟墙钟上限，总API调用硬上限720次，另需用户确认货币预算和密钥。正确子目标局部试验只能回答低层问题。只开发集调接口，冻结后使用未用于调参的实例；不把public_test301当盲测。效果明显依赖depth时另行报告观测差异，不宣称纯动作接口因果。到预算停，失败归入grounding/控制/反馈/预算，不自动再跑一轮。
3. **H-04小模型门**：只有H-03在至少两类问题出现可复核改善、且瓶颈在本地模型而不是执行器时，才申请转换/纠正数据及一个小VLM LoRA短训。先做≤200候选片段转换质量审计，含本人分层视觉抽查，不先重建全任务。训练的具体模型、数据release、GPU/步数/时间预算需另行登记；本报告不批准默认5000步。
4. **完整任务门**：局部筛选过门后另申请少量无专家前缀的完整任务，使用固定正式评测版本/初态/预算，比较完整成功、Q-score、交接错误、恢复成功、调用数和墙钟；不能从局部片段宣布全任务胜出。扩大到团队最终任务范围必须再次决定。

三人协作接口：Codex管语义动作契约/执行器/零样本和学生模型；队友一若团队采纳则负责重放转换与真实状态纠正数据；队友二保持通用RL路线，可共享事件/结果数据，不必为此立刻改成语言RL。三条线不互相热改，FM baseline不删除。
