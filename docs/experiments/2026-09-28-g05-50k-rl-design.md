## 1. 唯一主要假设与明确边界

假设：保持50k视觉语言表示、观察和控制接口不变，在线奖励能使**同一个任务条件化FM动作专家**更可靠地完成已有能力范围内的操作，并降低偏离专家轨迹后的失败概率。

不是重新训练一个机器人基座，不是端盘专用补丁，不是同时上MEM-Lite/新观察/新归一化。首批少量异质任务用于筛选方法；今后新版100任务规模须另行批准。

50k已有一条radio301完整官方成功，但尚无多实例SR；trash只有1024控制的未成功短诊断。不能预设50k成功率足够高，也不能把public_test301成功轨迹拿去RL、BC、critic训练或课程起点。RL优化结果不是FM/CE数值下降本身。

## 3. 算法决策：一个主候选，一个条件备选

主候选仍为**πRL/ReinFlow启发的Flow-Noise＋PPO**：让AE学更好的动作，而不只训练外部选择器。[πRL论文](https://arxiv.org/abs/2510.25889)在其模型上冻结VLM、更新动作专家；[ReinFlow](https://github.com/ReinFlow/ReinFlow)给出可学习随机flow转移的实现。它们没有直接支持这份G05-Qwen3.5/本地A100物理路径；这里是有依据的适配提案，不是已复现结论。

选择理由：当前有SFT动作能力与清楚的AE边界，可以直接检验“奖励能否修正执行策略”。不足是on-policy采样昂贵，长链概率和新critic都需审计。

**DSRL是若真实吞吐让PPO预算不可承受时的备选，不同时启动。** 它冻结整个FM，另学观察/任务条件化初始噪声策略，SAC可复用回放；变更小、更新便宜，但不等同于修改AE，受冻结生成器表达能力限制。原作者还有不同critic/计算代价变体，不能直接把RLinf某个π0示例的约500K参数量套到32×23的G05上。[作者实现](https://github.com/ajwagen/dsrl)、[RLinf示例](https://rlinf.readthedocs.io/en/latest/rst_source/examples/embodied/dsrl.html)

首轮不加GRPO/FPO/SAC-Flow四算法搜索。整条长轨迹分组比较会消耗大量环境样本；有可信训练状态时先用critic做逐决策信用分配。纯成功轨迹回灌SFT不是本提案中的PPO。

| FM动作专家 | 更新现有AE参数 | 先完整AE小学习率；若真实显存门不过，再单独审议AE-LoRA，不暗中换路线 |

| 价值网络V | 新建、独立optimizer | 训练时预测未来回报；不向冻结VLM反传，不输出机器人动作 |
| MEM-Lite及结果预测头 | 本轮不接入 | 父策略本来没有，不能说“这次RL训练了MEM” |

actor只见原三RGB、原proprio、task/frequency等原允许字段。critic可使用同观察的冻结特征＋训练特权状态（目标关系、对象相对位姿/速度、接触/抓持/关节、有效性mask），统一按目标/对象类型编码和集合聚合；不为每任务训练一个独立critic。当前真实状态可以进critic，但未来结果、演示剩余长度、泄漏eval答案不可以。

这是训练教师比部署策略知道得多，不是部署作弊。用独立数据通路和输入白名单测试，不能把critic字段拼入actor prompt。长远若错误是视觉识别或缺历史造成的状态混淆，冻结AE-RL未必可解；须依据失败分类再讨论VLM或记忆，而非首轮全解冻。

## 5. 让FM具备可核算的采样概率

现在的FM已有随机初始噪声，**不是完全确定策略**；确定的是给定噪声后的ODE积分。缺少的是能便宜、准确用于PPO的最终动作概率。

设c为原视觉语言条件，x_k为32×27中间动作，t_k=1−k/10。保留原均值更新：

`mu_k = x_k - 0.1 * v_theta(x_k, t_k, c)`

训练采样改为：

`x_(k+1)[valid] = mu_k[valid] + sigma_psi(x_k,t_k,c)[valid] * epsilon_k`

补齐4维在每一步仍为0；有效23维sigma严格为正且有上下界。`sigma`在此定义为**离散转移标准差**，不是SDE扩散系数；不再无意乘一次sqrt(dt)。10步中的每个随机转移都存原始样本，不能只存最后32步动作。

对给定旧采样路径，新/旧策略都用同一路径计算高斯log-prob之和，跨10步、32时序、23真实维度，共7360项；初始N(0,I)不随参数变化，在比率中抵消。这里是**完整latent路径概率**，不是声称算出了最终16×23环境动作的边际密度。

重算时旧x_k/x_(k+1)是固定、detach的数据，不用新策略重新生成路径来替代，也不沿旧采样随机图反传。首轮固定预处理/禁随机图像增强；新旧policy须对同一观察、同一latent、同一有效mask评分，不能把改变增广造成的概率差归为参数更新。

动作专家非因果耦合全部32步；后16步虽不执行，仍是潜变量，首轮保留完整路径评分。不能按“只执行16步”把路径评分截半；也不能把未来16步伪造为真实环境transition。

概率核算和求和用FP32，初次以batch一致性、相同参数时ratio≈1和微小参数扰动测试为门。不要对sigma=0计算概率。原版ReinFlow含log-prob长度/维数归一化开关；若采用该经验目标，必须承认它改变了比率，不称精确PPO。**本稿建议先用未归一化完整路径比率＋小更新＋KL停步**，不能遇到clip过高就隐式除以7360。若不可用，先定位精度/噪声/学习率，再明确修订目标。

首轮不额外引入中途latent裁剪；原controller已有的确定性限位必须原样保留并记录。若将来需要动作保护变换，保存变换前latent及变换后执行动作，所有策略/对照同规则，不拿截断后的样本冒充未截断高斯样本。[ReinFlow概率实现](https://github.com/ReinFlow/ReinFlow/blob/release/model/flow/ft_ppo/ppoflow.py)

## 6. 奖励：官方成功为目标，不先造复杂“好看分”

第一接入默认：**官方完整成功一次+1，其他0**，配合训练演示起点的短后缀课程，让成功信号可出现。并非要求基座从几分钟长任务起点纯随机摸索。碰撞/掉落/局部谓词先逐事件记日志，验证语义后才考虑加入奖励。

若任务有多个可审计目标关系，可加幅度较小的势函数差分：

`r'_t = r_success_t + beta * (gamma * Phi(s_(t+1),goal) - Phi(s_t,goal))`

Phi仅由可信当前目标/物理关系构造，正确处理AND/OR/NOT及对象绑定，归一化/版本固定。真正终止的Phi设0，计算截断则保留并bootstrap；不能在新episode接上旧势函数。该构造满足相应前提时可保持原折扣目标的最优策略，**随意追加距离/平滑/掉落奖惩没有此保证**。[势函数原论文](https://ai.stanford.edu/~ang/papers/shaping-icml99.pdf)

单布尔目标例如开收音机，直接数最终谓词仍然稀疏；不要假装BDDL自动解决所有dense reward。先用课程缩短credit距离；需要抓持等中间辅助时再验证通用事实层，而不是手写“radio_89距离多少给几分”。

不得把夹爪闭合、抓住任意物体、持续拿着、标注结束、模型自报DONE当成功。不默认所有放开都是掉落、所有接触都是碰撞、所有非最终目标物都是抓错（工具/门可能必要）。奖励测试必须覆盖拿起放下刷分、开关反复刷分、原地保持、必要的暂时退步、完成后继续累计、终止套利。先成功率，之后才考虑时间/平滑性的辅助目标。

## 7. chunk奖励、折扣、GAE与结束

一个环境决策是从同一观察产生32步后，实际执行m≤16步。把真实逐控制奖励折扣累积：

`R_chunk = sum_(i=0..m-1) gamma_control^i * r_i`

`Gamma_chunk = gamma_control^m`

critic TD残差：`delta = R_chunk + Gamma_chunk * V(next) - V(current)`，真正终止时next项为0。GAE只沿同一episode的真实chunk递推；lambda也明确使用chunk时间，部分chunk可按m/16缩放。去噪内部10步不额外消耗环境时间或扣环境gamma。

候选gamma_control=0.9998，对满16控制约0.996805；不是把0.99错误用到每个30Hz控制（2539步后约8e−12）。参数仍要按实际episode长度锁定，不宣传通用于所有长任务。collector截断可bootstrap，成功/不可逆真正终止不可bootstrap；官方任务定义的有限时限到期与单纯采集预算截断需区分。永远保留reset前final observation；崩溃/失联不是负例终止，要标invalid并隔离。

每条经验至少存：原actor观察/processor版本、critic状态及validity、task/source-instance/episode/seed、全部采样latent、旧log-prob/value、32步原动作、实际执行23D动作和m、逐控制reward/目标谓词、terminated/truncated及原因、final observation、两个时钟、policy/source/reward版本。

当前eval脚本只写部分执行动作/held/时钟和合成录像，未保存RL所需原三路输入、latent、概率、逐步reward；**已有视频不能直接充当PPO replay buffer**。

## 8. 一次更新、探索和防遗忘

1. 固定rollout策略版本，采一小批多起点轨迹；先看是否真的有成功/失败或可信进展差异。
2. 首批数据先训练critic，比较其预测与实际return，而不是只看value loss变小。全0稀疏reward不能冒充有监督信号；优先改合法课程起点，不空跑几千更新。
3. 计算returns/GAE；失败回合不把所有动作都同等判负，成功回合也不把所有动作都当专家。
4. 对同一批on-policy经验做少量PPO epoch，再收新数据；不把过期轨迹无限重播当on-policy。
5. 每个更新混少量原train演示FM监督，覆盖原五任务，保护未RL任务；原验证/测试绝不使用。BC辅助和PPO数据流分开，示范没有本RL采样概率，不能直接放进PPO actor目标。
6. 保存小规模中间快照、optimizer/critic/noise头/RNG和版本；保留原50k，恢复必须核policy版本。没有可继续的同策略数据就重采，不把旧buffer错配新log-prob。

可写为`L_actor = L_PPO + lambda_BC * L_FM(train_demos)`；critic有独立value损失，探索头一起更新。首轮先不叠entropy bonus及多个新正则。FM锚是模仿约束，不是精确KL。若另加reference KL，参考的原ODE条件转移是Dirac，不能直接算高斯到零方差的有限KL；可定义同非零噪声参考链，或明确使用速度/动作距离代理，二者不能混称。

噪声先小、归一化空间施加、反归一化后检查真实关节/底盘变化；不能把所有维度的0.1当一样安全，也不能为了稳定屏蔽底盘。建议初始离散sigma=.01、候选界[.003,.03]只是待校准数，不是已测最佳值。

部署候选仍为**原10步FM、不加新转移噪声**，仅使用RL更新后的AE；原初始随机噪声保留，不能称完全确定推理。必须实际比较训练随机采样与此部署模式；若收益只在加噪模式出现，不宣称已改善原FM部署。也不为快一点先改10步为4步。

## 9. 训练起点与分割：先让奖励可学到

- 从TRAIN实例的真实演示复放/完整仿真状态恢复接近目标的起点；先最后一小段，再更早、更长，最后从原始reset。原task指令不改成没训过的人工子目标。
- 必须验证关节、物体速度、接触/抓持约束、controller内部状态和相机时钟；只复制物体pose不是合格的课程reset。无法可靠恢复时如实回退完整专家前缀复放，并把前缀控制/耗时计入资源账。
- 课程/起点只在训练环境管理器和奖励侧；actor看不到演示帧号、剩余距离、oracle intent。短后缀课程成功率不能称自主完整任务SR。
- 首个接入可只用radio，但方法验证至少2–3种异质机制，候选radio、拾垃圾、清理盘子食物；仅任务名候选，不在缺元数据时捏造实例/seed已批准。统一一个actor、reward provider和训练器。
- episode 5%留出和public_test及其派生片段全部排除；新RL分割再按源实例分组。确认实例映射后登记精确train/dev/test清单。public_test301仅保留为已反复使用的开发回归，不能声称盲测，也不拿它选课程。
- 训练任务均衡采样，完整成功/局部失败分报；未RL任务可用原五任务train的BC保持、独立留出测遗忘。无跨任务证据不宣称已具备100任务通用性。

通过后另议一次方法筛选预算（例如总100k真实控制或12h墙钟，先到为止，含配对评测，**尚未批准**），一个主候选，不多算法/参数网格。方法门需原50k与RL用相同合法实例、policy seeds、原始reset、完整任务预算、renderer和执行16步规则。可讨论2任务×2新实例×2seed/策略的小矩阵，但先根据吞吐核算能否纳入预算；数量太少只作方向信号，给原始n/N而非虚假精确结论。

## 11. 算力的首要瓶颈及可复用工程

现有50k两回合实际3563控制/223调用/1924.9536秒，含两次冷启动约1.85控制/秒；FM调用中位数约.49s。仅按本批全程比例外推10k控制约90分钟、100k约15小时，**不是稳定吞吐测量**，不含RL反传，持续reset可能省去冷启动、增加并发也不保证线性。

第一优先级是常驻场景和可信连续reset，不是先更换算法或扩大batch。当前`native_full_profile.session`硬限定物理GPU3、原reset/load计数，并非四卡RL环境管理器；多环境必须另写新适配、私有runtime和时钟/动作回归，不能删除断言即宣布兼容。当前eval loop也忽略了env.step返回reward，需要接入审计过的reward provider。

建议先一张GPU做模型采样/更新、一张做常驻仿真；模型更新阶段暂停该轮采样，保证on-policy版本。过门后再测试一模型worker＋2–3独立sim worker、模型batch；不预设能同时放下或能填满四卡。冻结VLM能省反传，前缀cache的实际尺寸需测；cache按observation/version有界管理，不存无限KV。

保持决策时三相机RGB与原成像规格；仅减少真正不消费的中间观测/重复包装/录像I/O，每个真实物理步仍算reward、终止和必要事件。现在已有同步/少渲染措施，不能重复声称全部开销未优化。跨环境可流水，同一环境必须保持“当前观察→当前决策”的时钟协议。

[RLinf BEHAVIOR接入](https://rlinf.readthedocs.io/en/latest/rst_source/examples/embodied/behavior.html)公开覆盖R1Pro/23D及PPO，但页面仍列2025的50任务实例和π0/π0.5/OpenVLA-OFT，不是G05。其[系统优化](https://rlinf.readthedocs.io/en/latest/rst_source/resources/blog/behavior_system_optimization.html)可参考常驻/按需观察/多进程；25×不是A100保证。源码适配可以复用思路和组件，不先替换整个已核验2026环境、控制器或renderer。本轮未安装RLinf、未改共享环境、未访问A800节点。

## 12. 如何判断有效和何时停止

主要：同条件官方完整任务n/N及其不确定性；另报课程局部n/N、最终满足目标关系、成功用时、有效抓持/非计划脱手/错误交互/停滞、未训练任务退化。训练reward上升与eval成功提高分开；FM/CE仅遗忘诊断，允许小幅变化，不能以最低loss选RL权重。

停止/诊断触发：概率复算不一致、无奖励差异、critic无可用信号、动作越界/显著抖动、PPO clip近全饱和/路径KL异常、恢复错误、训练与部署采样效果分裂、奖励与官方结果脱钩、原能力明显丢失、预算到期。重复同一故障不自动追加一轮。

区别几类失败：actor识别/选错目标（表示/条件问题）、已正确接近但接触失误（AE-RL合适候选）、同图像需不同历史动作（缺记忆，reactive策略信息不足）、reward投机（奖励问题）、环境reset/动作时钟不一致（工程问题）。不能统一叫“RL没收敛”。

## 13. 后续实现边界与讨论中的决定

计划接口为`sample_with_trace / score_trace / value / reward / reset_from_train_state / collect / update / evaluate`。模型owner负责AE采样/评分与冻结保真，RL owner负责trainer/critic/rollout，数据owner负责合法演示起点和结果语义；先确认是否已有队友分支，避免重复实现。此稿由Codex负责，不擅自重新分配团队任务。

建议先决定：

1. 是否按主候选更新AE、冻结VLM，而非先做冻结全基座的DSRL？默认建议前者；吞吐门失败时才转后者。
2. 是否接受训练使用TRAIN演示起点课程、正式评测仍从原始reset？默认建议接受，否则稀疏长任务可能在小预算内完全没有学习信号。
3. 接入门通过后，再确认2–3任务、精确实例/seed、唯一实施owner及方法门预算。不得用当前讨论代替这份预登记。
