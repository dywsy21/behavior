## 2. 算法与超参

Flow-Noise式on-policy PPO：在原FM十次Euler更新上加条件高斯噪声，保存完整路径，用新旧路径概率比做PPO；不是把FM loss叫作log-prob，也不是未经适配的某论文原版。

| 项目 | E2实际值 |
| --- | --- |
| 概率/KL | 完整 `10×32×23=7360` 项求和，不除以维数；包括尚未执行的后16个预测位置 |
| 探索 | 每次FM transition额外sigma初始0.01、学习范围0.003–0.03，归一化latent单位 |
| 部署 | 关闭上述额外transition噪声；保留原FM初始标准高斯噪声 |
| 优化器 | AdamW，weight_decay=0；betas/eps未覆盖默认 |
| 候选LR | AE `1e-8`，noise `1e-7`，critic `1e-4` |
| 更新步幅 | PPO clip=0.05；actor＋noise合并梯度范数裁剪0.5，critic同0.5 |
| 回溯 | 候选scale `[1,.5,.25,.125,.0625,.03125]`；同batch维持缩小LR，新batch重置候选LR |
| 接受门 | 每条已收集路径KL≤0.01，并且当前minibatch PPO surrogate不恶化；拒绝完整恢复参数/Adam/梯度 |
| PPO复用 | 每批最多2 epochs、minibatch 8 chunks逐个梯度累计；回溯耗尽则提前结束本批更新 |
| critic | 公开冻结2048维特征→LayerNorm→256/Tanh→1；每批2次全批MSE更新 |
| 信用分配 | 每真实控制gamma=0.9998；每chunk GAE lambda=0.95；优势整批标准化 |
| 辅助BC | `L_actor = L_PPO + 0.1 L_FM_BC`，每次更新轮流取五task之一的固定TRAIN中部窗口 |
| 零奖励批 | critic仍更新，actor跳过；连续3零奖励批或3零accepted-update批停止 |

没有entropy bonus、没有全程参考父策略KL、没有离线经验回放反复做PPO。BC仅五个固定窗口（episodes 0/200/400/600/800），不是五任务全数据随机采样；KL只约束当前采样状态/latent，并不保证未采到的早期行为不变。BC样本虽固定，FM噪声仍按原训练生成。

原始记录中84次accepted AE LR：40次 `1e-8`，3次 `5e-9`，16次 `2.5e-9`，15次 `1.25e-9`，1次 `6.25e-10`，6次 `1.5625e-10`，2次 `3.90625e-11`，1次 `1.953125e-11`。即44/84低于候选起步LR。125候选中41拒绝：25次KL超限、16次surrogate不改善；三批因此未跑满两epoch。accepted max-path KL最大0.009997994、各更新该指标中位数0.009411827。LR小有路径敏感性依据，但此配方确实保守，不能将SFT LR直接平移或据此断言最优。

## 3. 奖励、课程与并发

- 真terminated不bootstrap；时间上限/采样截断使用reset前最终观察bootstrap，不跨reset计算GAE。
- 只对radio task0的原TRAIN实例1（episode0）和138（episode121）采RL。原逐task 5%留出、public_test不回灌。
- 两实例专家首次terminal分别1364、1192；初始先从官方reset真实回放1268、1096控制，剩96控制的专家末段交给模型。不是原初态自主完成，更不是状态瞬移。演示前缀计资源账，不计PPO样本。
- 同实例同起点连续成功3回合，前缀缩短96控制；最多到首次terminal前768控制。本轮1仅推进1268→1172；138始终1096。下一1076前缀已回放但未通过人审门，**没有从1076自主训练**。实际起点均已右手抓住radio，早段导航/抓取不在本轮PPO覆盖中。
- 每回合最多1024自主控制（30Hz约34.13模拟秒）；每批两个回合完成或128 chunks即收集结束。不是128个并行环境；本轮仅**2个**常驻仿真。
- GPU0采样/学习，GPU2/3各一个仿真、各8CPU核；不是四卡DDP。GPU1无专属learner但Kit有辅助context。120Hz物理、30Hz控制、原三RGB/PathTracing保持；CPU回滚和每候选整批重评分也有开销，未测占比不捏造GPU利用率。

## 5. 结论强度与后续讨论边界

原50k FP32与94-update FP32的固定6对完整任务结果0/6→0/6；有效抓持3/6→1/6只是小开发矩阵的中间信号。不能证明RL无效，也不能证明训练充分后仍无提升，更不能断言唯一问题就是步数。

**有效交互少＋更新保守＋阶段覆盖窄同时成立**。可以继续检验当前算法；有用的“多训练”必须增加新on-policy样本、奖励来源和课程覆盖，不是把同446条数据多刷几遍或让进程长时间等待。继续94-update还是从父50k重新做控制组尚无对照支持；前一报告“从50k重新开始、不继承delta”只是候选建议，**不是已证结论或执行硬约束**。不推荐当前delta替换部署父权重仍保持；这与保留它作为续训候选不矛盾。
