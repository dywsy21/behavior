# H39：真实关节限位和规划余量不能混为一谈

负责人：Codex-parent。2026-09-22 08:51：仅CPU设计/实现登记，尚未部署。H38工程门和SFT原评测源不热改。

## 已观察的问题

第一个heldout i1/base回合在832步固定前缀和12步静止检查后，首个模型动作尚未执行即终止。实际q[16]=1.047196626663208rad，小于机器人标定上限1.0471980571746826rad；距上限约1.43微弧度。它没有越过真实限位，但已进入原规划器预留的0.001rad余量。SafeServo.begin在区分动作前就用缩小的规划区间检查实际状态，因此这类起点可能导致所有动作被拒；Astra正在完成全45token保存态核验。

不能称为模型已经执行了错误抓取，也不能只把margin设为0。原失败要保留，缺失的逐tick实际q不能靠命令轨迹反推。

## 拟议改法

增加默认关闭的明确版本：先验证实际起点在标定硬限位内；规划仍优先使用原来的内缩区间。如果一个关节已经合法地贴近限位，则该次动作的规划区间最多扩展到这个实际起点，不允许继续向该限位逼近。其余关节沿用原余量，碰撞、目标姿态、速率、执行时长和抓取判据不变。

例如，右腕已经贴近上限时，可以保持它不动，让左手动作；也可以寻找向内回退的合法IK路径。不能把状态数值强行裁剪，再声称机器人实际已经退回。

本轮只做独立开关、回归测试和真实保存态重算，预算见`configs/semantic_robot/h39_joint_boundary_cpu_block.json`。如果需要把新执行器接入已训练的120步权重，必须保留原训练来源，显式登记新的共同评测执行器并让base/FT/检索基线一致；不能改旧manifest伪装同版本。新物理回合另行登记，不靠本CPU票追加重置。
