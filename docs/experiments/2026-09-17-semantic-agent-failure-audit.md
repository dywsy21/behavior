# H-05：语义微动作失败审计——不是一个“换大模型”就能解释的问题

2026-09-17，负责人 Codex。范围：审查 H-02/03 的接口、模型输入、harness 和控制器；18 次保存状态的静态诊断，**0 新物理控制、0 训练、0 生产修复**。原始失败运行不覆盖。本文给出修改建议，不表示建议已实现或取得成功率提升。

## 结论

首版有多处实质性缺口：**未微调小 VLM 配了简化执行循环；提示词的动作语法会被模型按字面照抄；视觉证据与抓取判断不可靠；缺少阶段、进度和恢复管理；控制器在限位附近不能保证命令效果，且不会自动中止。** 因此三条失败短测不能作为 Show-Harness 路线的有效否定，也不能把全部失败推给模型参数量。

更准确的归因是：语义动作的“看得懂—选得对—做得到—知道做没做到”四个环节尚未同时成立。现有小模型能力不足是因素之一，但当前试验不足以量化每项因素的独立贡献。

## 2. 先纠正实验配置：论文的两条路线不能混用前提

Show-Harness 第3.4节明确区分：强基础 VLM 的零样本模式配 harness；小 VLM 的快速模式经语义动作示范微调，才使用 task＋图像＋短历史的最小上下文。[论文](https://arxiv.org/html/2609.10522v1)

其官方 `docs/finetuned.md` 进一步要求 LoRA、prompt 版本、视角/动作方向、历史和部署模板匹配；当前发布的 adapter 不是 R1Pro 双臂/移动底盘权重。特别是某些单臂训练配置还在执行边界交换 FWD/BACK，不能不核对就套用。[官方微调部署说明](https://github.com/showlab/Show-Harness/blob/137d5718c3b7af0150764d8f9beeb252c9f2794a/docs/finetuned.md)

我们首版使用未做机器人微调的2B/4B，关闭思考，仅输出一个动作，但未补论文零样本路径的完整阶段管理、方向引导及恢复模块。**它是一个有意有界的小模型可行性探针，不是论文任一路线的等价复现。** 先追低延迟而缺少强模型质量参照，使试验难以判断接口能力上限；下一步应纠正这个优先级。

## 3. 微动作接口：机器合法不等于模型能正确使用

### 3.1 语法写法本身会误导

`src/semantic_robot/prompts.py:10` 用 `L|R|BOTH ... FINE|COARSE` 表示候选，缺少充分的单臂完整示例；唯一双臂示例又是对称上抬。实际自由输出证明模型会把这些符号直接抄进命令。语法树只是阻止非法字符串，不能补上缺失的动作理解。

建议：使用明确的工具字段或简单枚举，给完整单动作示例；先选择部位，再选择移动/转腕/开合及幅度，按阶段提供小动作集。比如“右手接近 radio”默认左手保持；真正需要双臂协调时才开放双臂模式。**不必增加新特殊 token，也不应把含 `L|BOTH` 的歧义输出擅自猜成某只手。** JSON/工具模式仍需验证，不能凭格式改善宣称动作有效。

完整语法共834个字符串，其中729个是左右手配对。它不代表模型均匀采样这些字符串，更不能按729/834推算双手动作概率；问题在于同时暴露过多自由度、同义表达和未指定的协调关系。

### 3.2 视觉坐标没有落到动作坐标

目前动作是机器人底盘坐标，模型看到的是头部和两个不断改变姿态的腕相机。给一句“FWD=+x，LEFT=+y”及四元数，并不能建立像素偏差到实际方向的可靠映射。转腕也围绕底盘轴，不等于绕工具自身轴。

这与论文强调“按参考视角定义动作方向”不同；其零样本控制 prompt 还显式描述腕图/全局图中目标相对夹爪的方向关系。[原控制提示词](https://github.com/showlab/Show-Harness/blob/137d5718c3b7af0150764d8f9beeb252c9f2794a/prompts/controller.txt)

建议保留底层真实23维，但给模型一个可校验的观察接口：用机器人 FK、合法相机标定在图上标夹爪中心和局部方向；或者明确参考相机，再由确定性变换解释视图相对微动作。深度方向需合法深度或经验证的视角引导，不能简单把屏幕左永远写成底盘LEFT；腕相机转动后映射也会变。目标框/接触点必须来自视觉检测/模型，不能读取仿真对象真值。

### 3.3 粒度和能力边界

2cm/5cm、5°/15°适合较粗接近，不足以覆盖按钮、薄盘边缘的所有精细接触。应按接近/对齐/接触阶段调节幅度，近处可测试毫米级小步及更短观察周期；大范围搜索则需更长但可中断的底盘段。不能把“始终更小”当最优。

`MODE CARRY`目前只是缩步、限速、禁止转腕，且要模型主动选择；它不检测食物、不自动调水平，也不保证防滑。阶段管理应在确认运输前设置相应约束，但不要在没有持物证据时假装进入安全运输。完整 `grasp(object)` 自动技能不是这次微动作路线的默认替代。

## 4. 感知不是全坏，但操作所需的事实判断未过关

本人复核了以上3状态×3视角共9张原始PNG，并结合原回合视频审核：

- radio初态：头图清楚显示桌上的收音机；左腕主要地板，右腕主要玻璃桌面及灯的反光，目标未在指间。模型能识别头图radio，但把腕图反光当作直接拍到灯，不能据简单“红物体检测通过”认定操控视觉通过。
- radio中段：右腕图中 radio 和闭合指尖存在二维重叠，单张图容易误判持有；头图及后续空抬录像显示它仍在桌上。模型却确定宣称“拿住”，再编造了不存在的搬桌任务。需要前后图像/夹爪开度/物体随手运动的交叉证据，不能只靠一张图的重叠。
- task3初态：头图为厨房和冰箱，两个腕图被近场深色结构大面积遮挡，看不到可确认在夹爪中的披萨。模型受任务文字影响，凭空描述“拿着披萨/盘子”。此时首先应寻找目标和改善视角，不是转腕维持所谓已抓住的盘。

建议把“目标在不在当前视图、接触区域能否看清、是否被遮挡、持物是确认/否定/未知”作为显式状态。保留头图全局视野，对有目标的腕图/接触区域保留更高分辨率或局部裁剪；提供上次动作前后图像对。单纯加长文字 CoT 可能只是让错误观察更流畅；本次简短观察提示也没有稳定纠正。

## 5. Harness：目前没有真正的进度闭环

现有 `user_text()` 每次放整个任务建议、当前三图、raw末端坐标/四元数、最近5条已执行字符串和上次数字回执。它**没有显式当前阶段、阶段完成条件、目标/手臂分工、前后视觉对照或无进展检测**。文字写着“不要反复空夹”并不能阻止2B实际空夹48次。

Show-Harness原控制 prompt 提供 STAGE、TARGET、AFFORD、DONE WHEN、recovery/proprio 等字段；恢复插件还会识别闭合后空夹并回退阶段。[控制 prompt](https://github.com/showlab/Show-Harness/blob/137d5718c3b7af0150764d8f9beeb252c9f2794a/prompts/controller.txt)、[恢复插件](https://github.com/showlab/Show-Harness/blob/137d5718c3b7af0150764d8f9beeb252c9f2794a/plugins/recovery/plugin.py)

建议共享一个轻量状态框架，而不是每任务写50套控制器：

`观察/搜索 → 接近 → 对齐 → 接触 → 验证持有 → 操作/运输 → 验证放置/效果`。

每任务prompt只填目标、顺序、手臂偏好和物理注意点；保留根据观察重规划。比如radio必须在“右手持有已有证据”后才能推进到“左手找按钮”，不能把完成CLOSE命令当阶段完成。

反馈要变成模型能直接利用且执行器也能强制处理的事件：`TRACKING_FAILED`、`JOINT_LIMIT_STALL`、`TARGET_NOT_VISIBLE`、`GRASP_UNVERIFIED`、`EMPTY_GRASP_SUSPECTED`、`NO_PROGRESS`。每个事件有测量来源和不确定性；连续无位移/同一无效动作、相反动作振荡触发有限恢复或重规划，而不是机械禁止一切重复。

注意不能照搬原恢复插件把中间夹爪宽度直接称为“已抓对”。R1Pro当前记录的是两指行程均值，不是指尖总间距；需本体校准并结合图像/合法接触信号。无法确认时保持UNKNOWN；官方任务成功独立判定，actor不可获取场景真值。

**此处无需先融合或训练MEM-Lite。** 普通可审计状态存储已足以补当前阶段/短历史/证据/恢复；只有验证确实缺长程记忆后再增加学习式记忆。

## 6. 执行器：动作语义在限位处会失去保证

原回合的全段汇总，而非局部接口门：

| 回合 | 最大末端位置误差 | 最大姿态误差 | 含关节限位裁剪的命令/控制帧 |
| --- | --- | --- | --- |
| radio4B | 10.03cm | 12.43° | 12 / 260 |
| task3 4B | 7.75cm | 14.25° | 32 / 617 |

源见 [原试验报告](2026-09-17-semantic-agent-pilot.md)。2cm微动作出现10cm量级残差，不能说只是“模型选得不好”。`control.py:141`先做无约束DLS，再把关节目标逐维裁到限位；接近边界时，该裁剪会破坏求解所得的笛卡尔运动关系。`feedback()`不论跟踪误差多大，状态都为 `EXECUTED_NOT_TASK_SUCCESS`。该名字没有冒称任务成功，但也没有告诉上层“本次微动作未按约定实现”，执行中更无持续偏差中止。

只读核对表明当前Jacobian的link行减1、浮动基座列偏移、相对坐标用法与本机OG原生IK一致；暂未发现足以定罪的简单索引/世界系混用错误。**限位裁剪、碰撞约束、奇异姿态及伺服收敛各占多少原因，尚未唯一定位**，不能据clip相关性就宣布数学根因已完全证明。

下一物理试验前的P0：

1. 跨初始/伸展/转腕/近限位姿态做FK有限差分与Jacobian、微动作方向/幅度验收；局部一次2mm门不代表全工作空间。
2. 用含关节上下界、速度界和信赖域的IK/QP或经验证的原生控制器；投影前后验证末端进度，必要时回退/缩步，不能只在求解后裁剪。
3. 按动作幅度和接触阶段定义位置/角度容差、持续限位及无进展阈值；触发即保持/终止该微动作并返回失败事件。30Hz伺服应执行保护，不等VLM下一次看图。
4. 验证躯干与双臂耦合、全程碰撞边界和正式remote FK；只查两末端距离不是全身碰撞检查。

这些修复属于独立执行可靠性，不应用追加模型训练来掩盖。0.8秒微动作内并非完全开环：有30Hz本体伺服；但没有新的VLM视觉决策，因此接触附近仍需更短/事件中断的观察周期。

## 7. 模型与速度的下一步取舍

当前不应先寻找另一个更小模型。推荐先建立一个强模型质量参照，再确定小模型能否通过微调达到所需行为：

- 本地候选 **Qwen3.8-27B**：官方为原生图文视频模型，强调规划和环境反馈能力；适合作为待测试的强参考，不是已验证的R1Pro最佳模型。27B仅bf16参数量估算约54GB，实际视觉/KV/运行显存和时延仍需门测；本轮未下载/运行。[官方模型卡](https://huggingface.co/Qwen/Qwen3.8-27B)
- **Qwen3.5-9B**可作同系、较低成本的容量对照，不保证足以解决空间推理；不要一次跑完整模型搜索。[官方模型卡](https://huggingface.co/Qwen/Qwen3.5-9B)
- 现有2B/4B保留作相同输入/相同harness对照及后续本体语义动作SFT候选。论文adapter不能未经映射审核直接复用。小模型训练应学经校验的观察→语义动作和纠偏，不照搬失败rollout作成功BC。
- 允许简短可核对观察和结构化动作，而不是一律禁止观察输出；但本次两行提示未解决问题，不能预设“开thinking”有效。以可见事实和方向准确率验证，再考虑速度。

原同图暖态2B/4B分别约325/690ms；完整闭环却只有0.23–0.27决策/墙钟秒，物理/渲染/留证占主要时间。模型推理速度并非此轮唯一或最大墙钟瓶颈；这支持先验证可靠决策。原物理仿真在等VLM时暂停，故“模型慢导致物体在等待期间掉落”不是这三回合的已支持解释；实际机器人异步控制仍需另验。

## 8. 推荐执行次序和停止条件（尚未启动）

1. **先修控制语义与保护，再改harness输入。** 上面的执行P0不过，不追加任务物理回合。
2. 从已有失败/正常画面建立15–30个手工审核的静态小集，覆盖目标未出现、遮挡、空夹、接近、近限位；检查对象/持有/方向，而不是只验红色或合法格式。用4B作锚，选一个强模型；逐项区分具体语法、阶段提示、动作集、视角标记和前后图，避免所有改变捆成因果结论。
3. 强参照在同一合法输入与预算下仍不能正确局部接近，则先查感知/接口，不立即大规模SFT。静态通过也不能直接放行完整任务成功率结论。
4. 通过控制与静态门后，才登记少量异质任务的局部闭环，固定实例/seed/前缀/预算，比较现有4B与强参照。先看方向、稳定接触、空夹后恢复，再看完整任务。
