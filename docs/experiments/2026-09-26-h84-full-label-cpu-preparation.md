## 统一标签规则

沿用`visual-grounding-v1`：严格JSON，`visibility=present|absent|uncertain`，坐标为整数0–1000；P必须有框、N/U空框。只框当前图中能识别的可见范围，不猜遮挡部分，且同图所有可识别同类物体都要覆盖。超过8个或实例边界无法定义的图先隔离，不任意截断为“已完整标注”。

- 收音机与黑色机器人壳体不能混淆；有辨识依据的局部把手可为P，单凭黑色外壳形似不行。
- 罐、垃圾桶、南瓜、蜡烛、坩埚、碗等按物体本身的可见轮廓；不能只框内部空洞、食品或高亮区域。
- “有食物的盘子”须图内确认食物，框包含可见盘体；盘背无食物证据是U，不沿时间推断。
- 冰箱/柜子/桌子/水槽要在校准中固定实例边界：框物体本身，不把把手当完整柜体，不把台面当水槽。柜门/柜体难以唯一归属时暂不放行；此类家具尚未通过校准，不能只凭JSON合法批量接受。
- 铰链罐近景要区分罐壁/金属扣件与机械手，反光片段身份不清为U。熟香肠须能识别为该类食品，远处橙色细线不足以确认。
- 本轮不产生拿住、接触、物体内含数量、柜门已关、成功/失败或机器人动作标签。视觉框正确也不证明动作可行。

质量门按查询分别报告，同时按task/相机分层：至少20个接受P和20个接受N，P/N precision各≥95%，候选覆盖≥50%，本人框复核正确率≥95%，不允许已知系统性错框。样本不足或未跑都写“未通过”，不能降低门槛补数。双模型一致只是候选，不是事实；U/冲突/格式错误进入人审或重试，不能暗转N。

## CPU工具与安全边界

`scripts/vlm_sft/prepare_full_annotation.py`读取六份固定SHA的H80元数据与两份固定人审记录，将42,240图登记为独立索引，再按split/task切660份最多192项的分片。ID绑定标注计划SHA、图像ID与查询；源图SHA、split及保护角色跟随每项。补齐或更改计划会产生新版本，不能混跑旧ID。

提供两个操作：

```bash
python scripts/vlm_sft/prepare_full_annotation.py prepare \
  --metadata artifacts/agentic-vlm-goal-20260918/h84_full_label_cpu_v1/source_metadata \
  --output /new/output/queue

python scripts/vlm_sft/prepare_full_annotation.py resume \
  --metadata artifacts/agentic-vlm-goal-20260918/h84_full_label_cpu_v1/source_metadata \
  --queue /existing/queue --attempts /closed/attempts.jsonl \
  --output /new/output/resume
```

操作必须用新输出目录，原RAW/旧队列不覆盖。完成前不会写队列seal。resume先从原封存元数据重新构造期望清单，逐文件核SHA和内容，拒绝缺片/重复/源图变更/跨队列结果/截断行。

状态含义：`PENDING`尚未生成；`RETRY_PENDING`有失败待重试；`QUALITY_PENDING`仅有合法候选；`REVIEW_REQUIRED`不确定待审。**这四种都不是已合格。** 没有自动APPROVED状态或训练导出入口，也没有加载模型、占GPU、终止进程的逻辑。

attempt记录只支持生成证据的排程/恢复。model/protocol SHA必须有，但形式合法的SHA不等于对应权重已由该记录验证；后续受监管GPU worker必须另核真实权重、输入token、输出原token、预算与运行身份，才能产生质量验收可用的证据。现有H83 launcher固定旧来源/run，不可直接改路径后当作H84全量runner；新类别teacher/critic接线仍须在独立冻结源码中做小校准。
