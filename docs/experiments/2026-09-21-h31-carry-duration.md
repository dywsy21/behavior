# H31：让持物半速和微动作时长上限一致

负责人 Codex；新实现默认关闭，独立源验收后才用于后继。正在运行的 H30/827 不切换版本。H31不是提高速度，也不是放宽抓取成功判据。

## 已定位的原因

TRAIN192/p388 原生采集实际完成 BACK、DOWN、CLOSE；下一次 UP 在发控制前被拒。保存的当前关节状态重新求解：1cm UP 可达，末端位置残差0.386mm、角度0.116°，机器人自碰撞余隙78.216mm。然而持物关节速度限制减半，计算需要44个控制步，旧 fine 的固定上限40步仍不变，因此报 DURATION_LIMIT_EXCEEDED。

闭爪时的接触偏移确实存在，但不是此次时长失败的必要条件：闭爪前相同关节状态配持物半速也需要45步。不能把 carry 改成 false 来绕过它；新代码只允许原来安全的慢动作花够时间。

## 修改边界

`ServoLimits.carry_duration_v1=True` 仅影响 `carry=True` 的 left/right/both 平移。原上限含5步末端停稳，故新上限为 `2 × (原上限 − 5) + 5`：micro/fine/coarse分别43/75/123步。不是每个动作都拖满上限；实际仍按关节位移计算，p388这次只需44步。30Hz下75步为2.5秒。

动作方向、位移、0.0125rad/步持物关节限速、IK精度、关节边界、自碰撞、笛卡尔轨迹走廊、实际反馈停滞/偏差检查均不改；torso/base/夹爪/旋转和未持物行为不变。已有可接受轨迹逐位相同。回合控制与墙钟上限仍独立生效，部分执行不自动算完成。

runner新增显式开关、工程门同版本绑定和结果记录；新反馈 `motion_timing` 区分所需关节轨迹步数、是否完成预检及有限上限，不声明实际持握或任务成功。旧执行profile缺省关闭，不能偷换旧数据语义。
